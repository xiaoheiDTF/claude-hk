# 经验学习（Learn）

> 阶段定位：总结对话中发现的问题，生成修正规则写入对应 skill 的补充上下文目录

---

## 一、核心目标

- 从当前对话上下文中提取经验教训
- 将修正规则写入目标 skill 的 `03-user-prompt-submit/*.md` 文件
- 下次触发该 skill 时，`03UserPromptSubmit.sh` 自动加载这些修正规则

---

## 二、工作流程

### 2.1 分析上下文

回顾当前对话，识别：

- 哪个 skill 在执行中出现了偏差、遗漏或错误
- 具体是什么问题（越界、遗漏、格式错误、逻辑错误等）
- 修正方向是什么

### 2.2 定位目标 skill

根据问题确定目标 skill 目录，格式：`.claude/skills/<skill-tag>/03-user-prompt-submit/`

已有 skill 列表（通过扫描 `.claude/skills/*/SKILL.md` 获取）。

### 2.3 生成规则文件

在目标 skill 的 `03-user-prompt-submit/` 目录下创建 `.md` 文件。

---

## 三、文件命名规范（约束）

文件按字母序加载，用前缀编号控制顺序：

```
01-修正-<描述>.md
02-补充-<描述>.md
03-约束-<描述>.md
04-经验-<描述>.md
```

类型前缀含义：

| 前缀 | 含义 | 场景 |
|------|------|------|
| 修正 | 修正已有行为 | skill 输出了不该输出的内容 |
| 补充 | 补充遗漏的场景 | skill 遗漏了某些情况 |
| 约束 | 增加限制条件 | skill 越界做了不该做的事 |
| 经验 | 记录最佳实践 | 使用中发现的更优做法 |

编号规则：

- 新文件编号 = 目录下已有 `.md` 文件数量 + 1
- 同类文件按创建时间递增

### 3.1 文件内容格式（约束）

```markdown
# <类型>: <简短标题>

> 来源: <哪次对话或什么场景触发的>
> 目标: <期望修正什么行为>

<具体规则内容，简洁明确，可操作>

## 约束

- <如果有关联的硬约束，列在这里>
```

### 3.2 内容质量要求（约束）

- **简洁**：文件内容会直接注入为 `additionalContext`，避免冗长
- **可操作**：每条规则都能被 AI 直接执行，不需要二次解读
- **不重复**：写入前检查目录下已有文件，避免重复规则
- **单一职责**：一个文件解决一类问题，不混合多个不相关问题

---

## 四、操作步骤

1. **扫描目标目录**：读取目标 skill 的 `03-user-prompt-submit/` 下已有文件，了解已有规则
2. **总结问题**：从对话上下文中提取具体问题
3. **确认目标**：向用户确认要写入哪个 skill、写什么内容
4. **写入文件**：按命名规范创建 `.md` 文件
5. **验证**：确认文件已创建，内容格式正确

---

## 五、禁止事项（约束）

- 不修改目标 skill 的 `SKILL.md`，只修改 `03-user-prompt-submit/*.md`
- 不删除目标 skill 已有的补充文件（除非用户明确要求）
- 不修改 `scripts/` 下的脚本文件
- 规则内容不涉及具体业务逻辑，只涉及 skill 行为修正
