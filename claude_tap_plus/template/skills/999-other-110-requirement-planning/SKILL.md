# 需求文档生成

根据用户提供的功能需求，生成两类文档：

1. **前端页面组文档**（`M{序号}P{序号}-{名称}.md`）— 用户看到什么、怎么交互
2. **领域模块文档**（`domains/M{序号}-{名称}.md`）— 业务规则、对象关系、权限

## 执行流程

```
用户提供功能需求
  → Step 1: 识别前端项目、一级菜单、页面组
  → Step 2: 澄清关键信息（仅问必要的）
  → Step 3: 生成页面文档 + 领域文档
  → Step 4: 建立页面文档与领域文档的引用关系
  → Step 5: 自检必填章节完整性
```

### Step 1: 需求拆解

从用户需求中识别：

| 识别项 | 说明 |
|--------|------|
| 前端项目 | 哪些角色在哪些平台上使用（如 `saas-web`、`guest-uniapp`） |
| 一级菜单 | 按功能域分组（如 `M01-商品管理`、`M02-订单管理`） |
| 页面组 | 每个一级菜单下的页面（如 `M01P01-商品列表`、`M01P02-商品详情`） |
| 领域模块 | 跨页面共享的业务概念（如 `M01-商品`、`M02-订单`） |

**编号规则**：

| 文件 | 命名 | 示例 |
|------|------|------|
| 领域模块 | `M{序号}-{中文名称}.md` | `M01-商品.md` |
| 前端M文件夹 | `M{序号}-{中文菜单名}/` | `M03-POI管理/` |
| 前端P文档 | `M{序号}P{序号}-{中文页面名}.md` | `M03P01-POI管理.md` |

### Step 2: 关键信息澄清

缺少必要信息时，逐个提问澄清。**只问影响文档生成的关键问题**，不做完整访谈。

使用 `AskUserQuestion` 工具提问，每次只问一个问题。

典型需澄清项（按需选取，不强求全部）：

| 场景 | 需澄清的内容 |
|------|------------|
| 不清楚有哪些角色 | 系统有哪几类用户？ |
| 不清楚页面范围 | 每个模块下需要哪些页面？ |
| 不清楚交互细节 | 用户在{页面}上可以做哪些操作？ |
| 不清楚业务规则 | {功能}有什么特殊的限制或规则？ |
| 不清楚权限差异 | 不同角色看到的{页面}有什么区别？ |

### Step 3: 文档生成

按 [模板](references/templates.md) 生成文档。

**前端页面组文档**必须包含的章节：

| 章节 | 说明 |
|------|------|
| 页面定位 | 所属菜单、页面类型、核心使命 |
| 页面元素 | ASCII 线框图 + 区域说明（按视图组织） |
| 交互说明 | 用户操作 → 系统响应表格 |
| 异常路径 | 操作失败、超时、冲突等异常场景 |
| 页面状态 | 空状态 / 加载 / 正常 / 异常 |
| 数据需求 | 页面需要的数据，引用领域M文档 |
| 前置条件 | 进入页面的前提 |

**领域模块文档**必须包含的章节：

| 章节 | 说明 |
|------|------|
| 模块概述 | 核心职责和业务边界 |
| 需求来源 | 需求来自哪些前端页面 |
| 核心业务对象 | 业务概念、归属、量级、唯一性、生命周期 |
| 对象关系 | 1:1 / 1:N / N:M 关系 |
| 功能列表 | 整合多端同类功能 |
| 业务规则 | 核心规则、边界条件 |
| 权限规则 | 各角色的操作权限 |
| 依赖模块 | 与其他模块的依赖 |

**条件章节**（仅在相关时生成）：

| 章节 | 生成条件 |
|------|---------|
| 响应式说明 | 多端项目 |
| 跨端交互 | 多端联动场景 |
| 状态流转 | 有状态变化 |
| 并发约束 | 有并发场景（只描述业务约束） |

**禁止输出**：不定义字段、类型、表结构、API路径、技术选型。这些属于技术设计阶段。

### Step 4: 建立引用关系

页面文档的"数据需求"章节必须引用对应的领域文档：

```
| 数据需求 | 说明 | 领域模块 |
|---------|------|---------|
| {数据} | {用途} | [M01-商品](../../domains/M01-商品.md) |
```

领域文档的"需求来源"章节必须引用对应的页面文档：

```
| 前端项目 | 页面组 | 提供的需求 |
|---------|--------|-----------|
| saas-web | M01P01-商品列表 | 商品CRUD |
```

### Step 5: 自检

文档生成后，对照以下清单逐项检查：

**页面文档检查**：

- [ ] 页面定位（菜单、类型、使命）
- [ ] 页面元素（线框图 + 区域说明）
- [ ] 交互说明（操作 → 响应）
- [ ] 异常路径
- [ ] 页面状态（空/加载/正常/异常）
- [ ] 数据需求（引用领域文档）
- [ ] 前置条件

**领域文档检查**：

- [ ] 模块概述
- [ ] 需求来源（引用页面文档）
- [ ] 核心业务对象（概念、归属、量级、唯一性、生命周期）
- [ ] 对象关系
- [ ] 功能列表
- [ ] 业务规则
- [ ] 权限规则
- [ ] 依赖模块

**引用完整性**：

- [ ] 每个页面的数据需求都引用了领域文档
- [ ] 每个领域的需求来源都引用了页面文档
- [ ] 引用的文档编号和名称一致

## 输出

**语言**：中文

**目录结构**：

```
requirement/prds/
├── domains/
│   ├── M01-{领域名}.md
│   └── M02-{领域名}.md
└── {角色}-{平台}/
    └── M01-{一级菜单名}/
        ├── M01P01-{页面组名}.md
        └── M01P02-{页面组名}.md
```

**文件路径规则**：页面文档中引用领域文档使用 `../../domains/M{序号}-{名称}.md`。

- [澄清指南](references/interview-guide.md) — 关键信息澄清提问参考
