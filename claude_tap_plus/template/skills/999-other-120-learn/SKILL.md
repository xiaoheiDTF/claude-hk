# 学习进化技能

> 触发方式：`/999-other-120-learn`
> 编号：999-other-120-learn

---

## 一、核心目标

将技能在实际使用中发现的问题、修正或补充，写入对应技能的 `03-user-prompt-submit/` 目录。下次调用该技能时自动加载，实现学习进化。

---

## 二、工作流程

### 步骤 1：确认目标技能

从用户输入中识别要修正/补充的目标技能。支持以下输入方式：

- 技能编号：`/999-other-120-learn 003-1` → 目标 `003-1-develop-feature-tree`
- 技能名称：`/999-other-120-learn 功能点` → 目标 `003-1-develop-feature-tree`
- 直接描述问题：`/999-other-120-learn 003-2 场景完整性要求太死了` → 目标 `003-2-develop-bdd-scenario`

如果无法确定目标技能，列出所有可用技能供用户选择。

### 步骤 2：理解问题

从用户输入中提取：

- **问题描述**：技能在什么场景下表现不佳？
- **修正建议**：应该怎么改？
- **补充内容**：需要新增什么规则或示例？

如果信息不完整，主动追问，但不要过度提问。

### 步骤 3：读取目标技能现有上下文

读取目标技能的 `SKILL.md` 和 `03-user-prompt-submit/` 目录下已有的 MD 文件，确保：

- 新内容不与已有补充冲突
- 新内容不重复 SKILL.md 已有的规则
- 新内容是对现有规则的精确补充或修正

### 步骤 4：写入补充文件

在目标技能的 `03-user-prompt-submit/` 目录下创建 MD 文件。

**文件命名规范：**

```
{序号}-{类型}-{简述}.md
```

- 序号：控制加载顺序，已有文件最大序号 +1
- 类型：`修正` / `补充` / `经验` / `定制`
- 简述：2-5 个字的中文描述

示例：
```
01-修正-边界覆盖过于强制.md
02-补充-并发场景模板.md
03-经验-空状态判断经验.md
```

**文件内容规范：**

```markdown
# {标题}

> 来源：{简述发现问题的场景}
> 日期：{YYYY-MM-DD}
> 影响技能：{技能编号}

## 问题

{当前规则在什么情况下表现不佳}

## 修正/补充

{具体应该怎么做}

## 示例（可选）

{具体的场景示例}
```

### 步骤 5：确认生效

写入后告知用户：

- 文件路径
- 文件内容摘要
- 提醒：下次调用该技能时自动生效，无需重启

---

## 三、操作类型

### 修正（现有规则有问题）

当技能的某条规则在实际使用中导致不好的结果时：

1. 引用 SKILL.md 中的具体规则（章节 + 规则号）
2. 说明问题场景
3. 给出修正方案
4. 写入 `XX-修正-XXX.md`

### 补充（缺少某些规则）

当技能在某些场景下缺少指导时：

1. 说明缺少的场景
2. 给出补充规则
3. 写入 `XX-补充-XXX.md`

### 经验（使用心得）

记录使用过程中的发现：

1. 记录具体的使用场景
2. 记录发现的行为和结论
3. 写入 `XX-经验-XXX.md`

### 定制（项目特定）

针对当前项目的特殊约定：

1. 说明项目的特殊情况
2. 给出适配规则
3. 写入 `XX-定制-XXX.md`

---

## 四、查询能力

除了写入，本技能还支持查询现有补充：

- `/999-other-120-learn 列出 003-1` → 列出 003-1 的所有补充文件
- `/999-other-120-learn 查看 003-2 的 01` → 查看 003-2 的第 01 号补充
- `/999-other-120-learn 删除 003-3 的 02` → 删除指定补充文件（需确认）

---

## 五、禁止事项

- 禁止直接修改 SKILL.md（那是主规范，修改需走文档流程）
- 禁止写入与 SKILL.md 已有规则完全重复的内容
- 禁止写入空文件或无意义内容
- 禁止修改其他技能的 scripts/ 目录下的脚本文件
