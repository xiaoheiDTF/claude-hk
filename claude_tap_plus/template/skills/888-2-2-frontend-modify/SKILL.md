# 前端代码修改

> 根据 `project.md` 开发规范修改前端代码，**两轮确认后才动手写代码**

---

## 一、前置检查

读取本 skill 目录下的 `project.md`。

- 如果文件不存在或内容为空 → 提示用户先运行 `/888-2-1-frontend-project-init`，终止
- 如果文件中缺少本次修改需要的信息（如目录结构、组件规范、样式方案等） → 提示用户补充对应内容，终止

---

## 二、核心流程

### 第一轮：理解确认

#### Step 1：阐述理解

用自己的话描述对需求的理解：
- 要做什么（修改什么页面 / 新增什么组件 / 修复什么问题）
- 涉及哪些模块

#### Step 2：等待用户确认

向用户展示理解，等待确认。
- 用户说"确认/对/没问题" → 进入第二轮
- 用户提出修改 → 调整理解后重新展示，**不算确认**，必须再次等待用户明确确认
- 用户取消 → 终止

---

### 第二轮：方案确认

#### Step 3：展示线框图

用 ASCII 线框图展示 UI 变化的预期效果：

```
┌──────────────────────────────┐
│  导航栏: [返回] 页面标题       │
├──────────────────────────────┤
│                              │
│  ┌──────────────────────┐    │
│  │  卡片标题              │    │
│  │  描述文字...           │    │
│  │  ┌──────┐ ┌──────┐   │    │
│  │  │ 按钮A │ │ 按钮B │   │    │
│  │  └──────┘ └──────┘   │    │
│  └──────────────────────┘    │
│                              │
└──────────────────────────────┘
```

如果是修改现有页面，展示修改前后的对比。

#### Step 4：展示交互逻辑

描述页面/组件的交互行为：
- 用户操作 → 系统响应
- 状态流转（Loading → 成功/失败）
- 路由跳转逻辑
- 弹窗/提示触发条件

#### Step 5：展示文件影响树

用以下固定格式展示本次修改影响的所有文件：

```
标注说明：(+) 新增文件  (~) 修改现有文件  (-) 删除文件

前端根目录/
├── components/
│   └── XxxCard/
│       ├── XxxCard.vue           (+) 新增组件
│       ├── XxxCard.types.ts      (+) 类型定义
│       └── XxxCard.stories.ts    (+) Storybook
├── pages/
│   └── module/
│       └── xxxPage.vue           (~) 修改页面
└── api/
    └── xxxApi.ts                 (~) 新增接口方法
```

**格式约束**：
- 只展示本次修改涉及的文件，不展示无关文件
- 每个文件必须有标注和简述
- 文件路径必须与 `project.md` 中的目录结构一致
- 新文件必须放置在 `project.md` 规定的目录中

#### Step 6：等待用户确认

向用户展示线框图 + 交互逻辑 + 文件影响树，等待确认。
- 用户说"确认/开始/执行" → 进入第三轮
- 用户提出修改 → 调整方案后重新展示，**不算确认**，必须再次等待用户明确确认
- 用户取消 → 终止

---

### 第三轮：执行

#### Step 7：按方案实现

严格按已确认的方案和 `project.md` 的开发工作流执行：
- 文件放置到 `project.md` 指定的目录
- 组件风格、命名、样式遵循 `project.md` 的代码规范
- 样式使用 Design Token，不写硬编码值

#### Step 8：测试验证

- 运行构建命令，确保编译通过
- 运行测试命令，确保测试通过

---

## 三、开发约束

- **文件放置**：新文件必须放到 `project.md` 指定的目录中
- **组件风格**：必须与 `project.md` 中记录的组件规范一致
- **样式方案**：必须使用 `project.md` 中记录的样式方案
- **禁止**：不修改与本次需求无关的代码
- **禁止**：不引入 `project.md` 中未列出的新依赖
