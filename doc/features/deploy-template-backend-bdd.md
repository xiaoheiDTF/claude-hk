# 后端 BDD — 配置部署子命令

> 功能：`claude-tap-plus.exe` 新增 deploy 子命令，将模板目录部署到目标项目
> 模板位置：`claude_tap_plus/template/`
> 来源：功能点定义 + BDD 场景（9 条）

---

## 功能接口清单

| # | 功能接口 | 职责 |
|---|---------|------|
| F1 | **部署接口** | 接收目标路径，执行模板 → 目标的文件复制 |
| F2 | **模板校验接口** | 检查模板目录是否存在且结构完整 |
| F3 | **目标校验接口** | 检查目标路径是否有效 |
| F4 | **备份接口** | 对目标已有文件创建时间戳备份 |
| F5 | **文件过滤接口** | 决定哪些文件需要复制、哪些需要跳过 |

## 后端场景

### F1：部署接口

#### 正向场景

**F1-P1：首次部署到无 .claude/ 的目标项目**
> **来源**：BDD 1.1
> **数据前提**：目标路径 `/project-a/` 下无 `.claude/` 目录；模板目录完整（含 hooks/、skills/、lib/、scripts/、myRule/、settings.json、init.sh、dirs.conf）
> **请求**：deploy 子命令，目标路径 `/project-a/`
> **预期结果**：
> - `/project-a/.claude/` 目录创建成功
> - 模板中所有文件和目录结构完整复制到目标
> - `888-*/project.md` 文件存在且内容为空
> - 无 `settings.local.json`、无运行时产物文件
> - 命令退出码 0，输出部署成功信息
>
> **验证**：diff 模板目录与目标 `.claude/`，文件清单和内容完全一致

**F1-P2：再次部署覆盖旧版本**
> **来源**：BDD 2.1
> **数据前提**：目标路径 `/project-a/` 已有之前部署的 `.claude/`（hooks 版本旧）；模板中 hooks 已更新；目标有运行时产物（`.initialized`、`.python-state`、`.active`、日志目录）
> **请求**：deploy 子命令，目标路径 `/project-a/`
> **预期结果**：
> - hooks 通用文件更新为模板最新版
> - 运行时产物（`.initialized`、`.python-state`、`.active`、日志、`localLanguage/`）未被删除或修改
> - 备份已创建
> - 命令退出码 0
>
> **验证**：hooks 文件内容与模板一致；运行时产物内容与部署前一致；备份目录存在

**F1-P3：无变更重复部署**
> **来源**：BDD 2.2
> **数据前提**：目标 `.claude/` 与模板完全一致
> **请求**：deploy 子命令
> **预期结果**：
> - 文件内容不变
> - 备份已创建
> - 命令退出码 0
>
> **验证**：所有文件 hash 与执行前一致

## 附录：运行时生成文件清单

以下文件由系统在运行时自动生成，**不属于模板内容**，部署时必须排除。

### 1. 初始化标记

| 文件 | 创建者 | 内容 |
|------|-------|------|
| `.claude/.initialized` | `init.sh` | OS、Python 路径、时间戳 JSON |
| `.github/.issue-initialized` | `skills/001-1-issue-init/scripts/init.sh` | 标签体系初始化标记 |

### 2. 环境状态

| 文件/目录 | 创建者 | 内容 |
|-----------|-------|------|
| `.claude/.python-state` | `scripts/ensure_python.sh` | Python 状态（ready/failed/路径/版本） |
| `.claude/localLanguage/` | `scripts/ensure_python.sh` 下载 | 整个目录（含 Python 嵌入式运行时） |

### 3. 会话/技能状态

| 文件 | 创建者 | 内容 |
|------|-------|------|
| `.claude/skills/.active` | `skills/active.sh`（active_add） | 当前活跃的 `session_id\|skill_name` |

### 4. 日志

| 目录/文件 | 创建者 | 内容 |
|-----------|-------|------|
| `.claude/hooks/logs/*.log` | `hooks/base.sh` | hooks 统一日志（每日一个文件） |
| `.claude/hooks/lib/win32-foreground.log` | 平台特定模块 | Windows 前台日志 |
| `.claude/skills/log/*/*.log` | `skills/log.sh` | 每个 skill 的每日日志 |

### 5. 项目特有配置

| 文件 | 性质 |
|------|------|
| `.claude/settings.local.json` | 用户在使用过程中积累的权限白名单 |

## 待确认问题

| # | 问题 | 需确认原因 | 建议默认 |
|---|------|-----------|---------|
| Q1 | 模板中删除的文件（如旧 skill），部署时是否也从目标删除？ | 影响文件过滤逻辑和用户预期 | **只增不删**（更安全） |
| Q2 | 备份目录命名和位置？ | 影响备份接口实现 | 默认 `.claude.backup.{timestamp}/` 在目标项目根目录 |

| Q4 | 部分失败时的回滚策略 | 影响部署接口的失败处理复杂度 | **报错 + 提示用户从备份恢复** |
