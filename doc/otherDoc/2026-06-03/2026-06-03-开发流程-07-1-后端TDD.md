# 单项目开发流程 — 后端 TDD（Test Driven Development）

> 文档日期：2026-06-03
> 所属系列：单项目开发完整流程
> 阶段定位：根据后端 BDD 写单元测试，通过测试驱动代码实现

---

## 一、核心目标

- 从后端 BDD 场景生成单元测试
- 通过 Red-Green-Refactor 循环驱动代码实现
- 保证所有服务层和数据库逻辑符合后端 BDD

---

## 二、阶段职责

### 本阶段负责（约束）

- 从后端 BDD 场景生成可执行的单元测试
- 编写最小实现让测试通过
- 重构实现代码，保证测试仍通过
- 覆盖 Domain、Application、Infrastructure、API 四个层级

### 本阶段不负责（约束）

- 后端 BDD 场景编写 → 后端 BDD 阶段
- 接口契约定义 → Contract 阶段
- 前端组件开发 → 前端 CDD 阶段
- 集成测试、端到端测试 → 联调阶段

---

## 三、Red-Green-Refactor 流程

```
1. RED     → 从后端 BDD 生成测试，测试应失败
2. GREEN   → 写最小实现让测试通过
3. REFACTOR → 提取模式、优化算法，保证测试仍通过
```

---

## 四、测试分层

| 层级 | 测试内容 | 对应 BDD |
|------|---------|----------|
| Domain 层 | 领域规则、状态变更 | 领域规则 BDD |
| Application 层 | 用例编排、事务 | API 契约 BDD |
| Infrastructure 层 | 数据库操作、外部调用 | 数据持久化 BDD |
| API 层 | HTTP 协议、请求/响应格式 | API 契约 BDD |

---

## 五、代码模板

### 5.1 测试代码

```java
@Test
@DisplayName("{Scenario名称}")
void {methodName}() {
    // Given（来自后端 BDD 的数据前提）
    {Entity} {entity} = {Entity}.builder()
        .{field}({value})
        .build();

    // When（来自后端 BDD 的功能接口调用）
    {ResultType} result = {service}.{method}({params});

    // Then（来自后端 BDD 的预期结果）
    assertThat(result.{field}()).{matcher}();
}
```

### 5.2 实现代码

```java
// GREEN 阶段：最小实现
@Service
public class {Service} {
    public {Result} {method}({Params}) {
        // 最小实现让测试通过
    }
}

// REFACTOR 阶段：提取模式、优化算法
```

### 5.3 参数化测试

```java
@ParameterizedTest
@CsvSource({
    "100, 200, 300",    // 正向
    "0, 0, 0",          // 空数据
    "999, 1, 1000"      // 边界值
})
void testWithMultipleData(int input1, int input2, int expected) {
    // 同一逻辑覆盖多组输入输出
}
```

## 六、测试数据管理

| 方案 | 说明 |
|------|------|
| 测试夹具（Fixture） | 预定义数据集，每个 Scenario 一组 |
| Builder 模式 | 灵活构造测试数据 |
| 数据库清理 | 每个测试后清理，保证隔离 |
| 参数化测试 | 同一逻辑覆盖多组输入输出 |

---

## 七、完成定义（约束）

满足以下所有条件后，后端 TDD 阶段结束：

- 每条后端 BDD 场景都有对应的测试用例
- 每个测试用例都通过
- 覆盖 Domain、Application、Infrastructure、API 四个层级
- 代码经过 REFACTOR 阶段，无重复逻辑

---

## 八、禁止事项（约束）

后端 TDD 阶段禁止：

- 跳过 RED 阶段直接写实现
- 为通过测试而硬编码返回值（GREEN 阶段允许临时硬编码，但 REFACTOR 阶段必须消除）
- 测试之间产生顺序依赖
- 修改测试来适配实现（测试来源是后端 BDD，实现应适配测试）

---

## 九、产物保护（约束）

测试代码一旦生成，进入锁定状态：

- **只增不改** — 允许追加新测试用例，禁止修改或删除已有测试用例
- **修改需特定技能** — 确需修改已有测试时，必须使用专门的修改技能（而非在开发过程中随意改动），并记录修改原因
- **锁定范围** — 测试方法签名、断言条件、测试数据均受保护；测试基础设施（Fixture、Builder、工具函数）的 refactor 不在此限制内
