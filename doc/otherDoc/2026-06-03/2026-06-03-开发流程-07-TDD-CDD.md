# 单项目开发流程 — TDD / CDD 代码实现

> 文档日期：2026-06-03
> 所属系列：单项目开发完整流程
> 阶段定位：根据 BDD 写单元测试，通过测试驱动代码实现

---

## 一、核心目标

- 后端 TDD：测试服务层和数据库逻辑
- 前端 CDD：组件级测试，保证 UI 和状态行为正确
- 流程：根据 BDD 写单元测试 → 通过测试驱动代码实现 → 保证所有逻辑符合 BDD

---

## 二、后端 TDD 模板

### 2.1 Red-Green-Refactor 流程

```
1. RED    → 从 Backend BDD 生成测试，测试应失败
2. GREEN  → 写最小实现让测试通过
3. REFACTOR → 提取模式、优化算法，保证测试仍通过
```

### 2.2 代码模板（Java/Spring）

```java
// RED: 从 Backend BDD 生成测试
@Test
@DisplayName("{Scenario名称}")
void {methodName}() {
    // Given（来自 BDD 的 Given）
    {Entity} {entity} = {Entity}.builder()
        .{field}({value})
        .build();

    // When（来自 BDD 的 When）
    {ResultType} result = {service}.{method}({params});

    // Then（来自 BDD 的 Then）
    assertThat(result.{field}()).{matcher}();
    assertThat(result.{field}()).{matcher}();
}

// GREEN: 最小实现
@Service
public class {Service} {
    public {Result} {method}({Params}) {
        // 最小实现让测试通过
    }
}

// REFACTOR: 提取模式、优化算法
```

### 2.3 后端测试分层

| 层级 | 测试内容 | 对应 BDD |
|------|---------|----------|
| Domain 层 | 领域规则、状态变更 | 领域规则 BDD |
| Application 层 | 用例编排、事务 | API 契约 BDD |
| Infrastructure 层 | 数据库操作、外部调用 | 数据持久化 BDD |
| API 层 | HTTP 协议、请求/响应格式 | API 契约 BDD |

## 三、前端 CDD 模板

### 3.1 Storybook 驱动开发

```typescript
// 从 Frontend BDD 生成 Storybook
export const {ScenarioName}: Story = {
  args: {
    {prop}: mock{Entity}({
      {field}: {value},
    }),
  },
  play: async ({ canvasElement, step }) => {
    const canvas = within(canvasElement);

    await step('{BDD Then 描述}', async () => {
      expect(canvas.getByText('{expectedText}')).toBeVisible();
    });
  },
};
```

### 3.2 Vue 组件实现

```vue
<!-- 从 Story 驱动 -->
<template>
  <div class="{component}">
    <{ChildComponent} v-if="{condition}" />
    <{StateComponent} :status="{status}" />
  </div>
</template>
```

### 3.3 前端测试分层

| 层级 | 测试内容 | 对应 BDD |
|------|---------|----------|
| 组件级 | UI 渲染、状态变化 | Frontend BDD |
| 交互级 | 用户操作、事件触发 | Frontend BDD 交互场景 |
| 集成级 | API 调用、路由跳转 | 联调测试 |

## 四、多样数据问题的解决

### 后端测试数据

| 方案 | 说明 |
|------|------|
| 测试夹具（Fixture） | 预定义数据集，每个 Scenario 一组 |
| Builder 模式 | 灵活构造测试数据 |
| 数据库清理 | 每个测试后清理，保证隔离 |
| 参数化测试 | 同一逻辑覆盖多组输入输出 |

```java
// 参数化测试示例
@ParameterizedTest
@CsvSource({
    "100, 200, 300",    // 正常收藏
    "0, 0, 0",          // 空数据
    "999, 1, 1000"      // 边界值
})
void testWithMultipleData(int input1, int input2, int expected) {
    // ...
}
```

### 前端测试数据

| 方案 | 说明 |
|------|------|
| Mock 工厂 | `mockEntity()` 函数生成符合 schema 的数据 |
| MSW Handler | 按 BDD 场景定义不同的 Mock 响应 |
| Storybook Args | 每个 Story 对应一组测试数据 |

```typescript
// Mock 工厂示例
function mockItinerary(overrides?: Partial<Itinerary>): Itinerary {
  return {
    id: '1',
    status: 'PLANNED',
    days: [mockDayPlan()],
    ...overrides,
  };
}
```
