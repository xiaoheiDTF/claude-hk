# 单项目开发流程 — 后端 BDD（Backend）

> 文档日期：2026-06-03
> 所属系列：单项目开发完整流程
> 阶段定位：后端开发用 BDD 验证业务逻辑

---

## 一、核心目标

- 对应 Product BDD 场景，拆解成 API 调用、数据库操作、状态变更
- 对应 TDD：写单元测试，保证服务逻辑符合 BDD

---

## 二、后端 BDD 模板

```gherkin
Feature: {功能名称} - 后端

  Scenario: {正向场景}
    Given {前置数据状态}
    When 发送 {Method} 请求至 "{Path}"，请求体:
      """
      {请求体 JSON}
      """
    Then 响应状态码应为 {StatusCode}
    And 响应体应包含:
      """
      {预期响应}
      """
    And 数据库中 {表} 应 {状态变更}

  Scenario: {异常场景}
    Given {异常前置条件}
    When 发送 {Method} 请求至 "{Path}"
    Then 响应状态码应为 {ErrorStatusCode}
    And 响应体应包含错误码 "{ErrorCode}"

  Scenario: {边界场景}
    Given {边界条件}
    When 发送 {Method} 请求至 "{Path}"
    Then {边界预期结果}
```

## 三、示例（文章收藏）

```gherkin
Feature: 文章收藏 - 后端

  Scenario: 创建收藏记录
    Given 用户 user-001 存在
    And 文章 article-042 存在
    And 用户未收藏过文章 article-042
    When 发送 POST 请求至 "/api/v1/favorites"，请求体:
      """
      {"article_id": 42}
      """
    Then 响应状态码应为 200
    And 响应体应包含:
      """
      {"success": true, "favorite_id": 1}
      """
    And 数据库 favorites 表应新增一条记录

  Scenario: 重复收藏返回错误
    Given 用户已收藏过文章 article-042
    When 发送 POST 请求至 "/api/v1/favorites"，请求体:
      """
      {"article_id": 42}
      """
    Then 响应状态码应为 400
    And 响应体应包含错误码 "already_favorited"

  Scenario: 收藏数达到上限
    Given 用户已收藏 1000 篇文章
    When 发送 POST 请求至 "/api/v1/favorites"
    Then 响应状态码应为 400
    And 响应体应包含错误码 "favorite_limit_exceeded"
```

## 四、编写要点

| 要点 | 说明 |
|------|------|
| 拆解 Product BDD | 每个 Product BDD Scenario 对应一个或多个后端 Scenario |
| 关注 API 协议 | 请求/响应/状态码 |
| 关注数据变更 | 数据库的增删改 |
| 关注业务规则 | 幂等、上限、权限校验 |
