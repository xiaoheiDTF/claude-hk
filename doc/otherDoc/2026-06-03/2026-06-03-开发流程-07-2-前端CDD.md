# 单项目开发流程 — 前端 CDD（Component Driven Development）

> 文档日期：2026-06-03
> 所属系列：单项目开发完整流程
> 阶段定位：根据前端 BDD 写组件级测试，通过 Storybook 驱动组件实现

---

## 一、核心目标

- 从前端 BDD 场景生成组件级测试
- 通过 Storybook 驱动组件开发和验证
- 保证所有 UI/交互行为符合前端 BDD

---

## 二、阶段职责

### 本阶段负责（约束）

- 从前端 BDD 场景生成 Storybook Story 和组件测试
- 编写组件实现让 Story 和测试通过
- 覆盖组件级、交互级、集成级三个层级

### 本阶段不负责（约束）

- 前端 BDD 场景编写 → 前端 BDD 阶段
- 接口契约定义 → Contract 阶段
- 后端服务开发 → 后端 TDD 阶段
- 端到端测试 → 联调阶段

---

## 三、Storybook 驱动开发

```
1. Story  → 从前端 BDD 生成 Storybook Story
2. 组件   → 编写组件让 Story 渲染正确
3. 测试   → 在 Story 中编写交互测试，验证 UI 行为
```

---

## 四、测试分层

| 层级 | 测试内容 | 对应 BDD |
|------|---------|----------|
| 组件级 | UI 渲染、状态变化 | 前端 BDD UI 展示场景 |
| 交互级 | 用户操作、事件触发 | 前端 BDD 交互场景 |
| 集成级 | API 调用、路由跳转 | 联调测试 |

---

## 五、代码模板

### 5.1 Storybook Story

```typescript
export const {ScenarioName}: Story = {
  args: {
    {prop}: mock{Entity}({
      {field}: {value},
    }),
  },
  play: async ({ canvasElement, step }) => {
    const canvas = within(canvasElement);

    await step('{前端 BDD Then 描述}', async () => {
      expect(canvas.getByText('{expectedText}')).toBeVisible();
    });
  },
};
```

### 5.2 组件实现

```vue
<!-- 从 Story 驱动 -->
<template>
  <div class="{component}">
    <{ChildComponent} v-if="{condition}" />
    <{StateComponent} :status="{status}" />
  </div>
</template>
```

### 5.3 Mock 工厂

```typescript
function mock{Entity}(overrides?: Partial<{Entity}>): {Entity} {
  return {
    id: '1',
    status: 'PLANNED',
    ...overrides,
  };
}
```

---

## 六、测试数据管理

| 方案 | 说明 |
|------|------|
| Mock 工厂 | `mockEntity()` 函数生成符合 schema 的数据 |
| MSW Handler | 按前端 BDD 场景定义不同的 Mock 响应 |
| Storybook Args | 每个 Story 对应一组测试数据 |

---

## 七、完成定义（约束）

满足以下所有条件后，前端 CDD 阶段结束：

- 每条前端 BDD 场景都有对应的 Story
- 每个 Story 的交互测试都通过
- 覆盖组件级、交互级两个层级（集成级在联调阶段完成）
- 组件在不同 UI 状态下的渲染正确（Idle / Loading / Success / Error / Empty）

---

## 八、禁止事项（约束）

前端 CDD 阶段禁止：

- 跳过 Story 直接写组件
- 在 Story 中定义接口契约（Mock 响应结构由 Contract 阶段决定）
- Story 之间产生状态依赖
- 修改 Story 来适配组件（Story 来源是前端 BDD，组件应适配 Story）

---

## 九、产物保护（约束）

Story 和组件测试一旦生成，进入锁定状态：

- **只增不改** — 允许追加新 Story 和测试用例，禁止修改或删除已有 Story 和测试用例
- **修改需特定技能** — 确需修改已有 Story 或测试时，必须使用专门的修改技能（而非在开发过程中随意改动），并记录修改原因
- **锁定范围** — Story 的 args、play 函数中的断言、Mock 工厂的默认值均受保护；Storybook 配置和装饰器的调整不在此限制内
