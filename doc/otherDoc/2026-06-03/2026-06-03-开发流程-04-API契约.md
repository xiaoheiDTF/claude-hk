# 单项目开发流程 — API 契约 / 数据结构

> 文档日期：2026-06-03
> 所属系列：单项目开发完整流程
> 阶段定位：所有前后端调用通过契约对齐

---

## 一、核心目标

- 所有前后端调用都通过契约对齐
- 后端实现契约 → 前端调用契约 → 保证前后端同步

### 输出内容

| 项目 | 说明 |
|------|------|
| URL / Method | 接口地址和 HTTP 方法 |
| Request 结构 | 请求体字段、类型、校验规则 |
| Response 结构 | 响应体字段、类型 |
| 状态码 / 错误码 | 成功/失败的 HTTP 状态和错误码 |

---

## 二、契约模板

```
接口：{Method} {URL}
功能：{功能描述}

请求体（Request）:
  {字段1}: {类型} — {说明} — {是否必填}
  {字段2}: {类型} — {说明} — {是否必填}

响应体（Response 200）:
  {字段1}: {类型} — {说明}
  {字段2}: {类型} — {说明}

错误响应:
  400: {错误码1} — {说明}
  401: unauthorized — {说明}
  404: not_found — {说明}
  500: internal_error — {说明}
```

---

## 三、示例（文章收藏）

```
接口：POST /api/v1/favorites
功能：收藏一篇文章

请求体:
  article_id: int — 文章 ID — 必填

响应体（200）:
  success: bool — 是否成功
  favorite_id: int — 收藏记录 ID

错误响应:
  400: already_favorited — 文章已收藏
  401: unauthorized — 未登录
  404: article_not_found — 文章不存在

接口：DELETE /api/v1/favorites/{article_id}
功能：取消收藏

响应体（200）:
  success: bool — 是否成功

错误响应:
  404: not_favorited — 未收藏该文章
```

---

## 四、契约编写原则

| 原则 | 说明 |
|------|------|
| 前后端 Review | 契约定义后必须前后端共同确认 |
| 统一错误格式 | 所有接口使用统一的错误响应结构 |
| 字段与 BDD 对齐 | 请求字段来自 BDD 的 Given，响应字段来自 BDD 的 Then |
