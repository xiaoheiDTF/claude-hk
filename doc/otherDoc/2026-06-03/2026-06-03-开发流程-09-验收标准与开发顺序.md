# 单项目开发流程 — 验收标准与开发顺序

> 文档日期：2026-06-03
> 所属系列：单项目开发完整流程
> 阶段定位：每个功能点的可验证标准，以及开发顺序

---

## 一、验收标准（Acceptance Criteria）

### 核心原则

- 每个功能点都有可验证标准
- 这些可以直接用于手动/自动测试
- 验收标准来源于 Product BDD 的 Then 子句

### 验收清单模板

```markdown
## {功能名称} 验收清单

### 功能验收
- [ ] {AC1：来自 BDD Scenario 1}
- [ ] {AC2：来自 BDD Scenario 2}
- [ ] {AC3：来自 BDD 异常场景}

### 边界验收
- [ ] {边界条件1}
- [ ] {边界条件2}

### 性能验收
- [ ] {响应时间要求}
- [ ] {并发要求}

### 安全验收
- [ ] {权限检查}
- [ ] {数据脱敏}
```

### 示例（文章收藏）

```markdown
## 文章收藏 验收清单

### 功能验收
- [ ] 登录用户可以收藏文章
- [ ] 收藏成功后图标高亮
- [ ] 重复收藏提示"已收藏"
- [ ] 未登录点击收藏弹出登录框
- [ ] 取消收藏后状态恢复

### 边界验收
- [ ] 收藏数达到 1000 时提示上限
- [ ] 文章被删除后收藏自动失效

### 性能验收
- [ ] 收藏接口响应时间 < 200ms

### 安全验收
- [ ] 只能操作自己的收藏记录
- [ ] 收藏接口需要登录态校验
```

## 二、开发顺序

```
1. 写 功能点 + Rules
2. 写 BDD 场景（前后端统一）
3. 后端：
   ├─ 写 API + Service
   └─ 写 Backend BDD → TDD
4. 前端：
   ├─ 写 组件 + UI 状态
   └─ 写 Frontend BDD → CDD
5. 测试：
   ├─ 联调
   └─ 自动化 E2E
6. 验收：
   └─ 对照 BDD + AC 确认功能完成
```

---

## 三、完整链路图

```
功能点（Feature / Scope）
    ↓
BDD 场景（前后端统一验收标准）
    ↓
┌──────────────┴──────────────┐
后端 BDD                     前端 BDD
    ↓                           ↓
TDD（单元测试）             CDD（组件测试）
    ↓                           ↓
后端代码                    前端代码
    └──────────────┘
         ↓
联调 + E2E
    ↓
验收（对照 BDD + AC）
```

---

## 四、总结

| 关注点 | 核心内容 |
|--------|---------|
| 核心驱动 | 功能点 + Rules + BDD |
| 前后端对齐 | UI 状态 + API 契约 + 验收标准 |
| 测试可复用 | BDD 场景 → 自动化测试 |
| 不做 | 不用背景/市场分析，不用复杂 PRD |
| 只做 | 可落地、可测试、可自动化的规范 |
