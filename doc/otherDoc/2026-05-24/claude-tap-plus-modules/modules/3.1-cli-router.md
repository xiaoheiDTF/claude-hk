# 3.1 CLI Router 模块设计

> 来源于 09-module-functional-design.md §3.1
> 2026-05-24 设计：MVP 只做当前需求的命令集。

## 命令总览与模块归属

CLI Router 是唯一用户入口，所有命令按功能分发到对应模块处理。按模块归属如下：

```text
claude-tap-plus <command>
│
├── Proxy 模块 (3.4) ─────────── API 代理与 trace 记录
│   ├── claude [args...]           → 启动 Claude Code 代理
│   ├── kimi [args...]             → 启动 Kimi CLI 代理
│   └── (无子命令，默认)           → 自动检测并启动代理
│
├── Session 模块 (3.8) ────────── Session 索引与快照
│   ├── session-collect [flags]    → 扫描本机 session/trace 建索引
│   ├── session-find [flags]       → 按条件查询 SQLite 索引
│   ├── session-import [flags]     → 从外部目录导入 traces
│   ├── session-push [flags]       → session 快照收集（已有）
│   ├── session-pull [flags]       → session 恢复（已有）
│   └── session-status [flags]     → session 存储状态（已有）
│
├── Issue Mirror 模块 (3.9) ──── GitHub Issue 本地镜像
│   └── serve                       → 启动本地 HTTP 服务
│        └── 内含 Scheduler (3.12) → 定时治理 stale/blocked issue
│
├── Sandbox 模块 (3.13) ──────── Git Worktree 隔离工作区
│   ├── sandbox init                → 初始化 sandbox 环境
│   ├── sandbox create <name>       → 创建 sandbox worktree
│   ├── sandbox list                → 列出所有 sandbox
│   ├── sandbox status [<name>]     → 查看 sandbox 状态
│   ├── sandbox open <name>         → 用工具打开 sandbox
│   ├── sandbox cd <name>           → 输出 sandbox 路径
│   ├── sandbox exec <name> -- <cmd>→ 在 sandbox 内执行命令
│   ├── sandbox diff <name>         → 查看 sandbox 与主项目差异
│   ├── sandbox apply <name>        → 应用 sandbox 变更到主项目
│   ├── sandbox sync <name>         → 同步 sandbox 分支
│   ├── sandbox remove <name>       → 删除 sandbox
│   └── sandbox doctor              → 检查 sandbox 健康状态
│
├── Tool Adapter 模块 (3.14) ─── Claude CLI 适配
│   ├── tool claude [options] [prompt]    → 启动 Claude Code（叠加 sandbox/trace）
│   ├── tool claude mcp <sub> [opts]      → Claude MCP 管理（add/list/get/remove/serve）
│   ├── tool claude auth <sub> [opts]     → Claude 认证（login/status/logout）
│   ├── tool claude plugin <sub> [opts]   → Claude 插件（install/list/enable/disable/...）
│   ├── tool claude project <sub> [opts]  → Claude 项目（purge）
│   ├── tool claude agents [opts]         → Claude 后台 agent 管理
│   ├── tool claude doctor                → Claude 健康检查
│   ├── tool claude install [target]      → Claude 安装
│   ├── tool claude update                → Claude 更新
│   ├── tool claude setup-token           → Claude token 设置
│   ├── tool claude ultrareview [opts]    → Claude 云端 review（后续）
│   ├── tool claude auto-mode             → Claude auto mode（后续）
│   ├── tool list                         → 列出可用工具
│   └── tool which <tool>                 → 查找工具路径
│
├── Sync 模块 (3.15) ──────────── 跨机器同步
│   └── sync                        → 同步 metadata/trace/session
│
└── 通用 ────────────────────────── 不归属特定模块
    ├── help / --help / -h          → 打印帮助
    └── version / --version         → 显示版本
```

### 命令分层

```text
第一层：子命令（必须第一个参数）
  claude | kimi | session-* | sandbox | serve | sync | help | version

第二层：子命令参数
  --tap-*    → Proxy 模块消费（--tap-target / --tap-port / --tap-verbose）
  --sandbox  → Tool Adapter 消费
  --tool     → Tool Adapter 消费
  --flag     → 各子命令自己的参数

第三层：透传参数
  --         → 后续参数原样传给目标工具（claude / kimi）
```

## 路由分发逻辑

```text
claude-tap-plus [args]
  │
  │ ── Tool Adapter 模块 (3.14) ──
  ├── args[0] == "tool"               → runTool(args[1:])
  │   ├── args[1] == "claude"         → runToolClaude(args[2:])
  │   │   ├── args[2] == "mcp"        → claude mcp <args[3:]>
  │   │   ├── args[2] == "auth"       → claude auth <args[3:]>
  │   │   ├── args[2] == "plugin"     → claude plugin <args[3:]>
  │   │   ├── args[2] == "project"    → claude project <args[3:]>
  │   │   ├── args[2] == "agents"     → claude agents <args[3:]>
  │   │   ├── args[2] == "doctor"     → claude doctor
  │   │   ├── args[2] == "install"    → claude install <args[3:]>
  │   │   ├── args[2] == "update"     → claude update
  │   │   ├── args[2] == "setup-token"→ claude setup-token
  │   │   ├── args[2] == "ultrareview"→ claude ultrareview <args[3:]>
  │   │   ├── args[2] == "auto-mode"  → claude auto-mode
  │   │   └── 其他                    → claude <args[2:]> (交互式 + options)
  │   ├── args[1] == "list"           → listAvailableTools()
  │   └── args[1] == "which"          → whichTool(args[2])
  │
  │ ── Proxy 模块 (3.4) ──
  ├── args[0] == "claude"             → runProxy(ClaudeClient, args[1:])
  ├── args[0] == "kimi"               → runProxy(KimiClient, args[1:])
  │
  │ ── Session 模块 (3.8) ──
  ├── args[0] == "session-collect"    → runSessionCollect(args[1:])
  ├── args[0] == "session-find"       → runSessionFind(args[1:])
  ├── args[0] == "session-import"     → runSessionImport(args[1:])
  ├── args[0] == "session-push"       → runSessionPush(args[1:])
  ├── args[0] == "session-pull"       → runSessionPull(args[1:])
  ├── args[0] == "session-status"     → runSessionStatus(args[1:])
  │
  │ ── 通用 ──
  ├── args[0] == "help" / --help      → printUsage()
  ├── args[0] == "version" / --version→ printVersion()
  │
  │ ── 后续模块占位 ──
  ├── args[0] == "serve"              → runServe(args[1:])           // Issue Mirror (3.9)
  ├── args[0] == "sandbox"            → runSandbox(args[1:])         // Sandbox (3.13)
  ├── args[0] == "sync"               → runSync(args[1:])            // Sync (3.15)
  │
  └── 其他                            → 自动检测并启动代理（兼容旧用法）  // Proxy (3.4)
        ├── 检测到 --claude           → runProxy(ClaudeClient, args)
        ├── 检测到 --kimi             → runProxy(KimiClient, args)
        └── 默认                      → runProxy(ClaudeClient, args)
```

### 分发规则

1. `args[0]` 匹配已知子命令 → 路由到对应模块处理函数。
2. `args[0]` 不匹配任何子命令 → 走默认代理模式（向后兼容当前行为）。
3. 后续模块（serve/sandbox/sync）预留路由，MVP 阶段输出 "not yet implemented"。
4. 每个处理函数只消费自己的参数，剩余部分按规则透传或报错。

#### A.3 `tool claude`（交互式会话）

映射 `claude` 的全部启动选项。claude-tap-plus 在此基础上叠加 sandbox 切换和 trace 代理。

```bash
# ── 基本启动 ──

# 在 sandbox 中启动 Claude Code 交互式会话
claude-tap-plus tool claude --sandbox fix-auth

# 不指定 sandbox 时，直接透传（等同直接调用 claude）
claude-tap-plus tool claude

# ── 会话恢复 ──

# 继续最近一次会话 (-c / --continue)
claude-tap-plus tool claude --sandbox fix-auth --continue

# 恢复指定会话 (-r / --resume)
claude-tap-plus tool claude --sandbox fix-auth --resume

# 恢复时创建新 session ID（不覆盖原始会话）
claude-tap-plus tool claude --sandbox fix-auth --resume --fork-session

# 按 PR 恢复会话
claude-tap-plus tool claude --sandbox fix-auth --from-pr 42

# 使用指定 session ID
claude-tap-plus tool claude --sandbox fix-auth --session-id <uuid>

# ── 非交互式模式 ──

# -p / --print：输出后退出（管道友好）
claude-tap-plus tool claude --sandbox fix-auth --print "解释这个函数"
claude-tap-plus tool claude --sandbox fix-auth -p "运行测试并报告结果"

# JSON 输出
claude-tap-plus tool claude --sandbox fix-auth -p "列出所有 TODO" --output-format json

# 流式 JSON 输出
claude-tap-plus tool claude --sandbox fix-auth -p "重构 auth" --output-format stream-json

# ── 模型与权限 ──

# 指定模型
claude-tap-plus tool claude --sandbox fix-auth --model sonnet
claude-tap-plus tool claude --sandbox fix-auth --model opus

# effort 级别
claude-tap-plus tool claude --sandbox fix-auth --effort high

# 权限模式
claude-tap-plus tool claude --sandbox fix-auth --permission-mode plan
claude-tap-plus tool claude --sandbox fix-auth --permission-mode bypassPermissions

# 预算限制（仅 --print）
claude-tap-plus tool claude --sandbox fix-auth -p "快速检查" --max-budget-usd 0.5

# ── 工具控制 ──

# 允许/禁用特定工具
claude-tap-plus tool claude --sandbox fix-auth --allowedTools "Bash(git *) Edit Read"
claude-tap-plus tool claude --sandbox fix-auth --disallowedTools "Bash(rm *)"

# 指定可用工具集
claude-tap-plus tool claude --sandbox fix-auth --tools "Bash,Edit,Read"

# ── Prompt 控制 ──

# 直接传入 prompt
claude-tap-plus tool claude --sandbox fix-auth "修复 OAuth token 刷新 bug"

# 追加系统 prompt
claude-tap-plus tool claude --sandbox fix-auth --append-system-prompt "Always write tests"

# 自定义系统 prompt（替换默认）
claude-tap-plus tool claude --sandbox fix-auth --system-prompt "You are a security auditor"

# ── MCP 配置 ──

# 加载 MCP 配置文件
claude-tap-plus tool claude --sandbox fix-auth --mcp-config ./mcp-servers.json

# 严格 MCP 模式（只使用指定配置）
claude-tap-plus tool claude --sandbox fix-auth --mcp-config ./mcp.json --strict-mcp-config

# ── 插件 ──

# 加载插件目录
claude-tap-plus tool claude --sandbox fix-auth --plugin-dir ./my-plugin

# 从 URL 加载插件
claude-tap-plus tool claude --sandbox fix-auth --plugin-url https://example.com/plugin.zip

# ── Agent 配置 ──

# 指定 agent
claude-tap-plus tool claude --sandbox fix-auth --agent reviewer

# 自定义 agent（JSON）
claude-tap-plus tool claude --sandbox fix-auth --agents '{"reviewer":{"description":"Reviews code","prompt":"You are a code reviewer"}}'

# ── Worktree 集成 ──

# 创建临时 worktree（Claude 原生 worktree，不同于 sandbox worktree）
claude-tap-plus tool claude --sandbox fix-auth --worktree
claude-tap-plus tool claude --sandbox fix-auth -w fix-auth-temp

# ── 其他选项 ──

# 设置会话名称
claude-tap-plus tool claude --sandbox fix-auth --name "auth-fix-session"

# 详细输出
claude-tap-plus tool claude --sandbox fix-auth --verbose

# 调试模式
claude-tap-plus tool claude --sandbox fix-auth --debug
claude-tap-plus tool claude --sandbox fix-auth --debug "api,hooks"

# 调试日志写入文件
claude-tap-plus tool claude --sandbox fix-auth --debug-file ./debug.log

# 添加额外可访问目录
claude-tap-plus tool claude --sandbox fix-auth --add-dir ../shared-lib

# IDE 集成
claude-tap-plus tool claude --sandbox fix-auth --ide

# Chrome 集成
claude-tap-plus tool claude --sandbox fix-auth --chrome

# 禁用 slash commands
claude-tap-plus tool claude --sandbox fix-auth --disable-slash-commands

# Remote Control 模式
claude-tap-plus tool claude --sandbox fix-auth --remote-control my-session

# JSON Schema 约束输出（仅 --print）
claude-tap-plus tool claude --sandbox fix-auth -p "列出文件" --json-schema '{"type":"object","properties":{"files":{"type":"array"}}}'

# 设置文件来源
claude-tap-plus tool claude --sandbox fix-auth --file file_abc:doc.txt

# 设置来源
claude-tap-plus tool claude --sandbox fix-auth --setting-sources user,project
```

#### A.4 `tool claude mcp`（MCP 服务器管理）

映射 `claude mcp` 全部子命令。


#### A.12 参数分层与路由规则

```text
claude-tap-plus tool claude [subcmd] [args...]

                    │       └── Claude 子命令：mcp/auth/plugin/project/agents/...
                    └── tap-plus 专属参数（--sandbox/--tap-*）
```

**路由规则：**

1. `tool claude` 后第一个 token 匹配已知 Claude 子命令（`mcp`/`auth`/`plugin`/`project`/`agents`/`doctor`/`install`/`update`/`setup-token`/`ultrareview`/`auto-mode`）→ 提取子命令，剩余参数透传。
2. 第一个 token 不匹配任何 Claude 子命令 → 视为 `claude` 交互式启动参数。
3. `--sandbox` 等 tap-plus 专属参数在路由层提取，不传给 Claude。
4. 所有 Claude 原生参数原样透传，不做校验或转换。

**示例流程：**

```text
输入: claude-tap-plus tool claude --sandbox fix-auth -p "hello" --model sonnet

解析:
  tap-plus 提取: --sandbox fix-auth
  Claude 透传:   -p "hello" --model sonnet
  执行: cd .sandboxes/fix-auth && claude -p "hello" --model sonnet
```

```text
输入: claude-tap-plus tool claude mcp add --transport http sentry https://mcp.sentry.dev/mcp

解析:
  Claude 子命令: mcp add
  Claude 透传:   --transport http sentry https://mcp.sentry.dev/mcp
  执行: claude mcp add --transport http sentry https://mcp.sentry.dev/mcp
```

```text
输入: claude-tap-plus tool claude auth status

解析:
  Claude 子命令: auth status
  Claude 透传:   (无)
  执行: claude auth status
```

#### B.1 命令语法

#### B.2 子命令一览

| 命令 | 说明 | MVP |

#### B.3 `session-collect`

扫描本机 Claude Code session 文件和 trace 文件，解析后写入本地 SQLite 索引。

```bash
# 扫描所有 session
claude-tap-plus session-collect

# 只扫描指定时间范围
claude-tap-plus session-collect --since 2026-05-01 --until 2026-05-24

# 强制全量重建索引
claude-tap-plus session-collect --rebuild

# 只扫描 trace（不扫 session）
claude-tap-plus session-collect --trace-only

# 详细输出
claude-tap-plus session-collect --verbose
```

**参数：**

| 参数 | 必需 | 说明 |
|------|------|------|
| `--since <date>` | 否 | 起始日期（YYYY-MM-DD），默认全量 |
| `--until <date>` | 否 | 截止日期 |
| `--rebuild` | 否 | 清空索引全量重建 |
| `--trace-only` | 否 | 只扫描 trace 文件 |
| `--session-only` | 否 | 只扫描 session 文件 |
| `--verbose` | 否 | 显示每个文件处理详情 |
| `--dry-run` | 否 | 只统计不写入 |

**输出：**

```text
[session-collect] Scanning ~/.claude/projects/...
[session-collect] Sessions: 142 found, 139 indexed, 3 skipped
[session-collect] Traces:   89 found, 87 indexed, 2 skipped
[session-collect] Associations: 74 strong, 13 weak
[session-collect] Skipped files:
  - a3f2...jsonl: invalid JSON at line 847
  - b7c1...jsonl: empty file
  - session-xxx.jsonl: missing session_id field
[session-collect] Done in 2.3s
```

**幂等规则：**
- 重复执行时，已索引且未修改的文件跳过。
- `--rebuild` 清空后全量重建。
- 无法解析的文件记录到 skipped 表。

```bash
# 指定输出格式
```

**参数：**

| 参数 | 必需 | 说明 |

| `--branch <name>` | 否 | 按 Git 分支筛选 |
| `--os <type>` | 否 | 按操作系统筛选（windows / macos / linux） |

| `--limit <n>` | 否 | 结果数量，默认 50 |
| `--sort-by <field>` | 否 | 排序字段：date / project / machine，默认 date |

#### C.12 `sandbox sync`

同步 sandbox 分支。

```bash
# 从远端 fetch（安全，不修改文件）
claude-tap-plus sandbox sync fix-auth --fetch

# 拉取远端更新到 sandbox
claude-tap-plus sandbox sync fix-auth --pull

# 推送 sandbox 分支到远端
claude-tap-plus sandbox sync fix-auth --push

# 同步主分支更新到 sandbox（rebase）
claude-tap-plus sandbox sync fix-auth --rebase-base
```

**参数：**

| 参数 | 必需 | 说明 |
|------|------|------|
| `<name>` | 是 | sandbox 名称 |
| `--fetch` | 否 | 只拉取远端信息（安全） |
| `--pull` | 否 | 拉取并更新 sandbox（需确认） |
| `--push` | 否 | 推送 sandbox 分支到远端（需确认） |
| `--rebase-base` | 否 | 将 sandbox rebase 到最新 base 分支 |

**安全规则：**
- `--fetch`：可自动执行，不修改任何文件。
- `--pull`：需要确认，可能产生冲突。
- `--push`：需要确认，影响远端。
- `--rebase-base`：需要确认，可能需要解决冲突。
