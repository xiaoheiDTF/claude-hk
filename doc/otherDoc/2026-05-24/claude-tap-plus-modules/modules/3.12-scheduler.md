# 3.12 Scheduler 模块

> 来源于 09-module-functional-design.md §3.12、05-scheduler.md

## 作用

1. 定时扫描 issue 状态。
2. 生成治理计划。
3. dry-run 输出计划。
4. 执行 stale、release、blocked/unblocked 等动作。

## 任务定义

| 任务 | 默认频率 | 动作 |
|------|---------|------|
| in-progress 提醒 | 6 小时 | 超 6 小时无活动则记录提醒，可选 comment |
| in-progress 释放 | 每天 | 超 7 天无活动则移除 assignee/in-progress，添加 stale 或 released |
| stale 标记 | 每天 | open 且 30 天无活动加 stale |
| stale 关闭 | 每天 | stale 后 7 天仍无活动则关闭 |
| 依赖阻塞检查 | 每天 | depends on 未关闭则加 blocked |
| 依赖解除检查 | 每天 | 依赖关闭后移除 blocked |

## 功能

### 功能 1：定时扫描

Scheduler 定期扫描本地 Issue Mirror 状态。

1. 支持配置扫描频率。
2. 支持按任务启停。
3. 服务启动后可自动运行。
4. 支持手动触发一次执行。

### 功能 2：治理计划生成

Scheduler 先生成计划，再决定是否执行。

1. 找出长时间无活动的 in-progress issue。
2. 找出 stale issue。
3. 找出依赖已解除的 blocked issue。
4. 找出依赖未关闭但未标 blocked 的 issue。
5. 计划中必须包含原因、目标 issue、建议动作。

### 功能 3：Dry-run

所有 scheduler 任务必须支持 dry-run。

1. dry-run 只输出计划。
2. dry-run 不修改 GitHub。
3. dry-run 仍可写本地审计日志，标记为 preview。

### 功能 4：执行与记录

执行模式下根据计划更新 GitHub 和本地状态。

1. 执行前记录 activity_log。
2. 执行失败记录失败原因。
3. 执行成功后触发 Issue Mirror 更新。
4. 同一个动作必须幂等，避免重复评论或重复释放。
