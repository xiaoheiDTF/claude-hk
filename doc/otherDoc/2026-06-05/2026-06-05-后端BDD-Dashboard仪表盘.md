## BF1: 统计概览接口

接口职责：聚合返回活跃会话数、待处理 Issue 数、活跃代理数、机器总数、项目总数。

### 正向场景

**BF1-S1：系统有正常数据，请求统计概览**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 3 条活跃会话、5 条 idle 状态 Issue、2 个活跃代理、4 台机器、3 个项目 |
| 请求 | 请求统计概览接口 |
| 预期 | 返回 5 项统计，数值分别为：活跃会话 3、待处理 Issue 5、活跃代理 2、机器 4、项目 3 |
| 来源 | F1-S1（规则 1） |

### 异常场景

**BF1-S2：数据库连接失败，请求统计概览**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库不可连接 |
| 请求 | 请求统计概览接口 |
| 预期 | 返回错误，错误信息表明数据获取失败 |
| 来源 | F1-S2（规则 1） |

**BF1-S3：统计查询超时**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中存在大量数据（会话 10000+、Issue 50000+），导致聚合查询耗时超过阈值 |
| 请求 | 请求统计概览接口 |
| 预期 | 返回错误，错误信息表明查询超时 |
| 来源 | F1-S3（规则 1） |

### 边界场景

**BF1-S4：系统无任何数据，请求统计概览**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中无任何会话、Issue、代理、机器、项目记录 |
| 请求 | 请求统计概览接口 |
| 预期 | 返回 5 项统计均为 0，不返回错误 |
| 来源 | F1-S4（规则 1） |

**BF1-S5：某项统计数字超过 999**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 1200 条 merged 状态 Issue（使待处理 Issue 统计涉及大量数据），活跃会话 5、活跃代理 2、机器 3、项目 2 |
| 请求 | 请求统计概览接口 |
| 预期 | 返回正确的统计数值，大数字不影响返回结构 |
| 来源 | F1-S5（规则 1） |

**BF1-S6：数据在两次请求之间发生变化**

| 项目 | 内容 |
|------|------|
| 数据前提 | 第一次请求返回活跃会话 3、待处理 Issue 5；请求后，另一个进程注册了 2 条新会话、领取了 3 条 Issue |
| 请求 | 第二次请求统计概览接口 |
| 预期 | 返回活跃会话 5、待处理 Issue 2，反映最新数据状态 |
| 来源 | F1-S6（规则 1） |

### 后端独有场景

**BF1-S7：并发请求统计概览，同时有新会话注册**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中当前有活跃会话 3 |
| 请求 | 两个请求同时到达统计概览接口，同时有 1 条新会话正在写入 |
| 预期 | 两个响应各自返回一个一致的数据快照，不会出现活跃会话数为 3 但其他关联计数为 4 的不一致情况 |
| 来源 | 并发安全（规则 4） |

**BF1-S8：统计涉及多个实体的聚合查询**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有会话、Issue、代理、机器、项目数据，活跃会话正在被关闭 |
| 请求 | 请求统计概览接口 |
| 预期 | 返回的 5 项统计基于同一时刻的数据快照，不会出现活跃会话已减少但待处理 Issue 仍按旧值返回的跨实体不一致 |
| 来源 | 跨实体一致性（规则 4） |

## BF2: 最近会话列表接口

接口职责：返回最近的会话记录，包含会话 ID、状态、项目名、机器名、注册时间，按时间倒序排列，支持分页。

### 正向场景

**BF2-S1：多条不同状态的会话，请求会话列表**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 4 条会话：A（active，project-x，user@host-1，14:32）、B（active，project-y，user@host-2，14:28）、C（closed，project-x，user@host-1，14:15）、D（active，project-z，user@host-3，14:10） |
| 请求 | 请求最近会话列表接口 |
| 预期 | 返回 4 条记录，按时间倒序排列（A→B→C→D），每条记录包含会话 ID、状态、项目名、机器名、注册时间 |
| 来源 | F2-S1（规则 1） |

### 异常场景

**BF2-S2：数据库不可达，请求会话列表**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库不可连接 |
| 请求 | 请求最近会话列表接口 |
| 预期 | 返回错误，错误信息表明数据获取失败 |
| 来源 | F2-S2（规则 1） |

### 边界场景

**BF2-S3：无任何会话记录**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中无任何会话记录 |
| 请求 | 请求最近会话列表接口 |
| 预期 | 返回空列表，不返回错误 |
| 来源 | F2-S3（规则 1） |

**BF2-S4：仅有 1 条会话记录**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中只有 1 条会话（active，project-x，user@host-1，14:32） |
| 请求 | 请求最近会话列表接口 |
| 预期 | 返回包含 1 条记录的列表，字段完整 |
| 来源 | F2-S4（规则 1） |

**BF2-S5：会话数量超过分页上限**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 50 条会话记录 |
| 请求 | 请求最近会话列表接口（默认分页） |
| 预期 | 返回第一页数据（最近 N 条），包含分页信息，不一次性返回全部 50 条 |
| 来源 | F2-S5（规则 1） |

**BF2-S6：所有会话均为 active 状态**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 5 条会话，全部为 active 状态 |
| 请求 | 请求最近会话列表接口 |
| 预期 | 返回 5 条记录，状态字段均为 active |
| 来源 | F2-S6（规则 1） |

**BF2-S7：所有会话均为 closed 状态**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 5 条会话，全部为 closed 状态 |
| 请求 | 请求最近会话列表接口 |
| 预期 | 返回 5 条记录，状态字段均为 closed |
| 来源 | F2-S7（规则 1） |

**BF2-S8：同一机器上有多条不同项目的会话**

| 项目 | 内容 |
|------|------|
| 数据前提 | 机器 user@host-1 上有 3 条会话（2 条 active 属于 project-x、1 条 closed 属于 project-y） |
| 请求 | 请求最近会话列表接口 |
| 预期 | 返回 3 条记录，机器名相同，通过项目名可区分 |
| 来源 | F2-S8（规则 1） |

**BF2-S9：会话 ID 为完整 UUID**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中 1 条会话，会话 ID 为 `abc123def456-7890-ghij-klmn-opqrstuvwxyz` |
| 请求 | 请求最近会话列表接口 |
| 预期 | 返回该条记录，会话 ID 完整返回，不截断不丢失 |
| 来源 | F2-S9（规则 1） |

**BF2-S10：会话刚注册，时间为当前时刻**

| 项目 | 内容 |
|------|------|
| 数据前提 | 1 条会话刚完成注册，注册时间为当前时刻 |
| 请求 | 立即请求最近会话列表接口 |
| 预期 | 该会话出现在返回列表顶部，时间为当前时间，不为空不为未来时间 |
| 来源 | F2-S10（规则 1） |

### 后端独有场景

**BF2-S11：会话注册与列表查询并发**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 3 条会话 |
| 请求 | 1 条新会话正在注册的同时，请求最近会话列表接口 |
| 预期 | 列表返回 3 条或 4 条均可接受（取决于注册是否已提交），但不会返回一个字段已写入而另一字段为空的半成品会话记录 |
| 来源 | 并发安全（规则 4） |

**BF2-S12：会话正在关闭的同时查询列表**

| 项目 | 内容 |
|------|------|
| 数据前提 | 会话 A 正在被关闭（状态从 active 变为 closed），同时请求最近会话列表接口 |
| 预期 | 列表返回中会话 A 的状态要么是 active 要么是 closed，不会出现中间状态或空值 |
| 来源 | 实体状态机转换（规则 4） |

## BF3: Issue 状态分布接口

接口职责：返回 Issue 按状态分组的计数，状态包括 idle、claimed、fixing、ready-for-pr、pr-created、testing、reviewing、merged。

### 正向场景

**BF3-S1：多种状态的 Issue，请求状态分布**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 20 条 Issue：idle 8、claimed 3、fixing 2、testing 1、merged 6 |
| 请求 | 请求 Issue 状态分布接口 |
| 预期 | 返回 5 种状态及对应计数，数值正确，各状态之间无遗漏 |
| 来源 | F3-S1（规则 1） |

### 异常场景

**BF3-S2：数据库不可达，请求状态分布**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库不可连接 |
| 请求 | 请求 Issue 状态分布接口 |
| 预期 | 返回错误，错误信息表明数据获取失败 |
| 来源 | F3-S2（规则 1） |

### 边界场景

**BF3-S3：无任何 Issue**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中无任何 Issue 记录 |
| 请求 | 请求 Issue 状态分布接口 |
| 预期 | 返回所有状态计数为 0，不返回错误 |
| 来源 | F3-S3（规则 1） |

**BF3-S4：所有 Issue 处于同一状态**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 15 条 Issue，全部为 merged 状态 |
| 请求 | 请求 Issue 状态分布接口 |
| 预期 | merged 计数为 15，其余状态计数为 0 |
| 来源 | F3-S4（规则 1） |

**BF3-S5：Issue 覆盖全部 8 种状态**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 Issue 覆盖全部状态：idle 2、claimed 2、fixing 2、ready-for-pr 1、pr-created 1、testing 1、reviewing 1、merged 3 |
| 请求 | 请求 Issue 状态分布接口 |
| 预期 | 返回 8 种状态及对应计数，数值正确，无遗漏 |
| 来源 | F3-S5（规则 1） |

**BF3-S6：某一状态数量远超其他状态**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 500 条 merged Issue，其余状态各 1 条（idle 1、claimed 1、fixing 1） |
| 请求 | 请求 Issue 状态分布接口 |
| 预期 | 返回全部状态计数，merged 为 500，其余各 1，大数值不影响返回结构中其他状态的计数 |
| 来源 | F3-S6（规则 1） |

**BF3-S7：Issue 状态变更后请求分布**

| 项目 | 内容 |
|------|------|
| 数据前提 | 第一次请求返回 idle: 8、claimed: 3；请求后，有 2 条 idle Issue 被领取变为 claimed |
| 请求 | 第二次请求 Issue 状态分布接口 |
| 预期 | 返回 idle: 6、claimed: 5，反映最新状态 |
| 来源 | F3-S7（规则 1） |

### 后端独有场景

**BF3-S8：查询分布的同时有 Issue 被领取**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 idle: 8、claimed: 3 |
| 请求 | 1 条 Issue 正在被领取（idle → claimed）的同时，请求 Issue 状态分布接口 |
| 预期 | 返回的各状态计数总和为 11（总数不变），不会出现 idle 减少了但 claimed 未增加的计数不一致 |
| 来源 | 并发安全（规则 4） |

**BF3-S9：多条 Issue 同时变更状态**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库中有 idle: 5、claimed: 5 |
| 请求 | 3 条 Issue 同时从 idle 转为 claimed，同时请求 Issue 状态分布接口 |
| 预期 | 返回的分布要么反映变更前（idle: 5、claimed: 5），要么反映变更后（idle: 2、claimed: 8），不会出现中间不一致状态（如 idle: 3、claimed: 7，总和不为 10） |
| 来源 | 竞态条件（规则 4） |
