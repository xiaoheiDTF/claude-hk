## 一、系统概述

`claude-tap-plus` 后端是一个基于 Go + SQLite 的轻量级 HTTP API 服务，主要服务于 Claude Code 等 AI 编程代理的会话管理和 Issue 协作流程。后端与前端代理（claude-tap-plus CLI）配合，实现多会话环境下的 Issue 原子领取、状态流转和会话追踪。

### 2.2 Issue 管理模块

**核心能力**：实现 GitHub Issue 的原子领取和状态流转，防止多 Agent 冲突。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 检查 Issue 状态 | `/api/issue/check` | POST | 批量查询指定仓库中 Issue 的当前状态，不存在时自动创建 idle 记录 |
| 领取 Issue | `/api/issue/claim` | POST | 乐观锁实现原子领取，支持幂等（同一 session 重复领取返回成功） |
| 释放单个 Issue | `/api/issue/release` | POST | 将指定 Issue 恢复为 idle（仅限当前持有者，终态不可释放） |
| 释放会话下所有 Issue | `/api/issue/release-session` | POST | 批量释放某 session 持有的所有非终态 Issue |
| 更新 Issue 状态 | `/api/issue/status` | POST | 仅允许当前持有者更新状态，驱动状态机流转 |

**Issue 状态机**：

```
idle → claimed → fixing → ready-for-pr → pr-created → testing → reviewing → merged (终态)
                                                    ↘ rejected (终态)
```

**状态说明**：
- `idle`：空闲，无人领取
- `claimed`：已被某 session 领取
- `fixing`：正在开发中
- `ready-for-pr`：开发完成，等待提 PR
- `pr-created`：PR 已创建
- `testing`：测试中
- `reviewing`：审核中
- `merged`：已合并（终态，不可释放）
- `rejected`：被打回（终态，不可释放）

### 2.3 Session 管理模块

**核心能力**：记录每次 Claude Code 会话的元数据，支持会话生命周期管理和查询。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 注册会话 | `/api/session/register` | POST | 新会话注册，同时 upsert machines 和 projects 表 |
| 关闭会话 | `/api/session/close` | POST | 标记会话为 closed，记录关闭原因 |
| 获取会话列表 | `/api/sessions` | GET | 支持按 machine_id、project_slug、status 过滤 |
| 获取会话详情 | `/api/session/{id}` | GET | 获取单个会话完整信息 |

**Session 状态**：
- `active`：活跃会话
- `closed`：已关闭

**自动清理**：启动时清理注册超过 24 小时仍处于 active 状态的会话。

### 2.8 会话详情子资源模块

**核心能力**：获取会话关联的 Issue、Token 统计和 Trace 文件信息。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 获取会话关联 Issue | `/api/session/{id}/issues` | GET | 查看某会话领取的所有 Issue |
| 获取会话 Token 统计 | `/api/session/{id}/tokens` | GET | 解析 trace 文件汇总 token 消耗 |
| 获取会话 Trace 文件 | `/api/session/{id}/traces` | GET | 查看 trace 文件元数据（大小、行数、日期） |

**Token 统计响应**：

```go
type SessionTokensResponse struct {
    SessionID    string `json:"session_id"`
    APICalls     int    `json:"api_calls"`
    InputTokens  int    `json:"input_tokens"`
    OutputTokens int    `json:"output_tokens"`
    CacheRead    int    `json:"cache_read"`
    CacheCreate  int    `json:"cache_create"`
    TotalTokens  int    `json:"total_tokens"`
}
```

**Trace 文件响应**：

```go
type SessionTracesResponse struct {
    SessionID string      `json:"session_id"`
    Traces    []TraceItem `json:"traces"`
}

type TraceItem struct {
    Path      string `json:"path"`
    SizeBytes int64  `json:"size_bytes"`
    LineCount int    `json:"line_count"`
    Date      string `json:"date"`
    Filename  string `json:"filename"`
}
```

**Token 统计实现**：通过 `TokenService` 解析会话对应的 JSONL trace 文件，逐行读取 `usage` 字段汇总 `input_tokens`、`output_tokens`、`cache_read`、`cache_create`。

**Trace 文件实现**：通过 `TraceService` 获取 trace 文件的 `os.Stat` 信息（大小）和行数统计，从路径中提取日期和文件名。

### 2.9 日志查询模块

**核心能力**：查询后端服务运行日志，支持按级别、日期过滤。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 获取日志 | `/api/logs` | GET | 按级别、日期过滤，支持限制返回条数 |

**查询参数**：

| 参数 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `level` | string | — | 日志级别过滤（DEBUG/INFO/WARN/ERROR） |
| `date` | string | 当天 | 日志日期，格式 YYYY-MM-DD |
| `limit` | int | 100 | 最大返回条数 |

**响应数据结构**：

```go
type LogsResponse struct {
    Logs []LogItem `json:"logs"`
}

type LogItem struct {
    Timestamp string `json:"timestamp"` // 如 "2026-06-01 20:56:28.000"
    Level     string `json:"level"`     // DEBUG/INFO/WARN/ERROR
    Source    string `json:"source"`    // 来源模块
    Message   string `json:"message"`   // 日志内容
}
```

**实现**：`LogService` 读取 logger 模块生成的日志文件（`YYYY-MM-DD.log`），通过正则表达式解析每行日志，支持大小写不敏感的级别过滤。

### 2.10 配置管理模块

**核心能力**：动态查看和修改系统配置，支持部分更新。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 获取配置 | `/api/config` | GET | 返回所有配置项键值对 |
| 更新配置 | `/api/config` | PUT | 部分更新指定配置项（返回更新后的完整配置） |

**配置项定义**：

| 配置键 | 类型 | 默认值 | 说明 |
|--------|------|--------|------|
| `log_level` | string | `"info"` | 日志级别（debug/info/warn/error） |
| `session_timeout` | int | `3600` | 会话超时时间（秒） |
| `max_concurrent` | int | `10` | 最大并发数 |
| `auto_claim` | bool | `true` | 是否自动领取 |
| `default_model` | string | `"claude-3-opus"` | 默认模型 |

**响应数据结构**：

```go
type ConfigResponse struct {
    Config map[string]interface{} `json:"config"`
}
```

**错误码**：

| 错误码 | HTTP 状态 | 说明 |
|--------|----------|------|
| `unknown_config_key` | 400 | 未知的配置键名 |
| `invalid_config` | 400 | 配置值不合法 |
| `invalid_json` | 400 | 请求体 JSON 格式错误 |
| `no_updates` | 400 | 请求体为空 |

### 2.11 基础设施服务

| 服务 | 说明 |
|------|------|
| 空闲监控（IdleWatchdog） | 每 30s 检查 proxy.json，持续空闲 10 分钟自动关闭后端 |
| 超时会话清理（CleanupService） | 启动时清理超过 24h 的 active 会话 |
| 系统状态聚合（StatusService） | 聚合活跃会话、代理、Issue、机器、项目的统计数据 |
| Token 统计（TokenService） | 解析 JSONL trace 文件汇总 token 消耗 |
| Trace 元数据（TraceService） | 获取 trace 文件大小、行数、日期等元数据 |
| 日志查询（LogService） | 解析后端日志文件，支持级别过滤和日期选择 |
| 配置管理（ConfigService） | 系统配置的读取和更新 |
| SQLite 存储 | 本地文件数据库，支持 machines、projects、sessions、issue_claims、config、proxies 六张表 |

### 2.6 系统状态模块

**核心能力**：聚合系统全局统计信息，供前端仪表盘和监控页面使用。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 系统状态概览 | `/api/status` | GET | 返回服务状态、版本、运行时间和聚合统计 |

```go
type StatusResponse struct {

    TotalProjects  int64 `json:"total_projects"`  // 项目总数
}
```

## 三、数据模型

### 3.1 machines 表
记录使用 claude-tap-plus 的机器信息。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| machine_id | TEXT UNIQUE | whoami@hostname |
| os | TEXT | windows/linux/macos |
| hostname | TEXT | 主机名 |
| username | TEXT | 用户名 |
| first_seen_at | DATETIME | 首次注册时间 |
| last_seen_at | DATETIME | 最后活跃时间 |

### 3.2 projects 表
记录 Claude Code 工作过的项目。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| project_slug | TEXT UNIQUE | 项目标识（从 transcript_path 解析） |
| project_cwd | TEXT | 项目工作目录 |
| first_seen_at | DATETIME | 首次出现时间 |
| last_seen_at | DATETIME | 最后活跃时间 |

### 3.3 sessions 表
记录每次 Claude Code 会话的元数据。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| session_id | TEXT UNIQUE | UUID |
| machine_id | TEXT | 关联 machines |
| os | TEXT | 操作系统 |
| project_slug | TEXT | 关联 projects |
| project_cwd | TEXT | 工作目录 |
| transcript_path | TEXT | 对话记录路径 |
| local_trace_path | TEXT | 本地 trace 文件路径 |
| model | TEXT | 使用的模型 |
| source | TEXT | startup/resume |
| status | TEXT | active/closed |
| registered_at | DATETIME | 注册时间 |
| closed_at | DATETIME | 关闭时间 |
| close_reason | TEXT | 关闭原因 |

### 3.4 issue_claims 表
存储 Issue 领取关系和状态流转。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| repo_full_name | TEXT | 仓库全名（如 owner/repo） |
| issue_number | INTEGER | GitHub Issue 编号 |
| issue_title | TEXT | Issue 标题（缓存） |
| status | TEXT | 当前状态 |
| session_id | TEXT | 领取者 session |
| claimed_at | DATETIME | 领取时间 |
| updated_at | DATETIME | 最后更新时间 |

**唯一约束**：`(repo_full_name, issue_number)`

### 3.5 proxies 表

存储已注册代理的信息，支持代理列表查询。

| 字段 | 类型 | 说明 |
|------|------|------|
| proxy_id | TEXT PK | 代理唯一标识（PID） |
| project_slug | TEXT NOT NULL | 关联项目 |
| status | TEXT NOT NULL DEFAULT 'active' | 代理状态：active / offline |
| registered_at | DATETIME NOT NULL | 注册时间 |
| last_ping_at | DATETIME | 最后心跳时间 |

**索引**：`status`、`project_slug` 列各有索引，支持按状态和项目过滤查询。

### 3.6 config 表

存储系统配置项，支持运行时动态修改。

| 字段 | 类型 | 说明 |
|------|------|------|
| key | TEXT PK | 配置键名 |
| value | TEXT | JSON 编码的配置值 |
| updated_at | DATETIME | 最后更新时间 |

**预定义配置项**：

| 键名 | 类型 | 默认值 | 说明 |
|------|------|--------|------|
| `log_level` | string | `"info"` | 日志级别 |
| `session_timeout` | int | `3600` | 会话超时（秒） |
| `max_concurrent` | int | `10` | 最大并发数 |
| `auto_claim` | bool | `true` | 是否自动领取 |
| `default_model` | string | `"claude-3-opus"` | 默认模型 |

## 七、部署方式

后端作为 claude-tap-plus CLI 的子进程自动启动：
1. CLI 启动时检查后端是否运行
2. 未运行时自动启动后端服务（随机端口）
3. 后端通过 IdleWatchdog 检测空闲，无会话时自动退出
4. 支持优雅关闭（SIGINT/SIGTERM）
