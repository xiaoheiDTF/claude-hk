# claude-tap-plus 后端功能设计文档

> 文档日期：2026-06-01
> 基于后端代码分析，描述已有功能及可扩展的功能设计。

## 一、系统概述

`claude-tap-plus` 后端是一个基于 Go + SQLite 的轻量级 HTTP API 服务，主要服务于 Claude Code 等 AI 编程代理的会话管理和 Issue 协作流程。后端与前端代理（claude-tap-plus CLI）配合，实现多会话环境下的 Issue 原子领取、状态流转和会话追踪。

### 2.2 Issue 管理模块

**核心能力**：实现 GitHub Issue 的原子领取和状态流转，防止多 Agent 冲突。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 检查 Issue 状态 | `/api/issue/check` | POST | 批量查询指定仓库中 Issue 的当前状态，不存在时自动创建 idle 记录 |
| 领取 Issue | `/api/issue/claim` | POST | 乐观锁实现原子领取，支持幂等（同一 session 重复领取返回成功） |
| 释放单个 Issue | `/api/issue/release` | POST | 将指定 Issue 恢复为 idle（仅限当前持有者，终态不可释放） |
| 释放会话下所有 Issue | `/api/issue/release-session` | POST | 批量释放某 session 持有的所有非终态 Issue |
| 更新 Issue 状态 | `/api/issue/status` | POST | 仅允许当前持有者更新状态，驱动状态机流转 |

**Issue 状态机**：

```
idle → claimed → fixing → ready-for-pr → pr-created → testing → reviewing → merged (终态)
                                                    ↘ rejected (终态)
```

**状态说明**：
- `idle`：空闲，无人领取
- `claimed`：已被某 session 领取
- `fixing`：正在开发中
- `ready-for-pr`：开发完成，等待提 PR
- `pr-created`：PR 已创建
- `testing`：测试中
- `reviewing`：审核中
- `merged`：已合并（终态，不可释放）
- `rejected`：被打回（终态，不可释放）

---

### 2.3 Session 管理模块

**核心能力**：记录每次 Claude Code 会话的元数据，支持会话生命周期管理和查询。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 注册会话 | `/api/session/register` | POST | 新会话注册，同时 upsert machines 和 projects 表 |
| 关闭会话 | `/api/session/close` | POST | 标记会话为 closed，记录关闭原因 |
| 获取会话列表 | `/api/sessions` | GET | 支持按 machine_id、project_slug、status 过滤 |
| 获取会话详情 | `/api/session/{id}` | GET | 获取单个会话完整信息 |

**Session 状态**：
- `active`：活跃会话
- `closed`：已关闭

**自动清理**：启动时清理注册超过 24 小时仍处于 active 状态的会话。

---

### 2.4 Proxy 管理模块

**核心能力**：管理本地代理注册，支持 trace-init 请求转发。

| 功能 | 端点 | 方法 | 说明 |
|------|------|------|------|
| 代理注册 | `/api/proxy/register` | POST | 注册代理 PID 和 URL |
| 代理注销 | `/api/proxy/unregister` | POST | 移除代理注册 |
| Trace 初始化转发 | `/api/proxy/trace-init` | POST | 将请求转发给所有注册的代理，返回第一个成功响应 |

---

### 2.5 基础设施服务

| 服务 | 说明 |
|------|------|
| 空闲监控（IdleWatchdog） | 每 30s 检查 proxy.json，持续空闲 10 分钟自动关闭后端 |
| 超时会话清理（CleanupService） | 启动时清理超过 24h 的 active 会话 |
| SQLite 存储 | 本地文件数据库，支持 machines、projects、sessions、issue_claims 四张表 |

## 三、数据模型

### 3.1 machines 表
记录使用 claude-tap-plus 的机器信息。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| machine_id | TEXT UNIQUE | whoami@hostname |
| os | TEXT | windows/linux/macos |
| hostname | TEXT | 主机名 |
| username | TEXT | 用户名 |
| first_seen_at | DATETIME | 首次注册时间 |
| last_seen_at | DATETIME | 最后活跃时间 |

### 3.2 projects 表
记录 Claude Code 工作过的项目。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| project_slug | TEXT UNIQUE | 项目标识（从 transcript_path 解析） |
| project_cwd | TEXT | 项目工作目录 |
| first_seen_at | DATETIME | 首次出现时间 |
| last_seen_at | DATETIME | 最后活跃时间 |

### 3.3 sessions 表
记录每次 Claude Code 会话的元数据。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| session_id | TEXT UNIQUE | UUID |
| machine_id | TEXT | 关联 machines |
| os | TEXT | 操作系统 |
| project_slug | TEXT | 关联 projects |
| project_cwd | TEXT | 工作目录 |
| transcript_path | TEXT | 对话记录路径 |
| local_trace_path | TEXT | 本地 trace 文件路径 |
| model | TEXT | 使用的模型 |
| source | TEXT | startup/resume |
| status | TEXT | active/closed |
| registered_at | DATETIME | 注册时间 |
| closed_at | DATETIME | 关闭时间 |
| close_reason | TEXT | 关闭原因 |

### 3.4 issue_claims 表
存储 Issue 领取关系和状态流转。

| 字段 | 类型 | 说明 |
|------|------|------|
| id | INTEGER PK | 自增主键 |
| repo_full_name | TEXT | 仓库全名（如 owner/repo） |
| issue_number | INTEGER | GitHub Issue 编号 |
| issue_title | TEXT | Issue 标题（缓存） |
| status | TEXT | 当前状态 |
| session_id | TEXT | 领取者 session |
| claimed_at | DATETIME | 领取时间 |
| updated_at | DATETIME | 最后更新时间 |

**唯一约束**：`(repo_full_name, issue_number)`

基于已有后端能力，以下是建议扩展的功能模块：

### 4.2 项目管理模块

**现状**：projects 表已存在，但无独立 API。

**可扩展功能**：

| 功能 | 端点 | 方法 | 说明 |

## 五、API 设计规范

### 5.1 统一响应格式

```json
{
  "success": true,
  "data": { ... },
  "error": null
}
```

错误响应：
```json
{
  "error": "error_code",
  "message": "human readable message"
}
```

### 5.2 分页规范

列表接口支持：
- `?page=1&page_size=20` — 分页参数
- `?sort=registered_at&order=desc` — 排序参数

### 5.3 过滤规范

列表接口支持多字段过滤：
- `?status=active` — 精确匹配
- `?machine_id=xxx` — 精确匹配
- `?project_slug=xxx` — 精确匹配

## 七、部署方式

后端作为 claude-tap-plus CLI 的子进程自动启动：
1. CLI 启动时检查后端是否运行
2. 未运行时自动启动后端服务（随机端口）
3. 后端通过 IdleWatchdog 检测空闲，无会话时自动退出
4. 支持优雅关闭（SIGINT/SIGTERM）
