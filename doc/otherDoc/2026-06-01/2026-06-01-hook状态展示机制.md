# Claude Code CLI — Hook 状态展示机制

> 创建时间：2026-06-01
> 所属模块：Hooks 系统
> 简述：梳理 Claude Code CLI 中 Hook 调用状态与结果的 4 种展示机制，包含配置示例和代码片段，为后续实现 Hook 状态面板提供参考。

---

## 背景

当前项目 hooks 系统在 `hook_output()` 中返回 JSON 给 Claude Code CLI，但调用状态和结果主要写入日志文件（`hooks/logs/`），用户在 CLI 聊天窗口中**无法直接感知** hook 的执行情况。本文梳理 4 种 CLI 原生支持的展示机制，并给出组合使用建议。

---

## 机制一：`systemMessage` — 在聊天界面显示消息

### 原理

任何 hook 的 JSON 输出中加入 `systemMessage` 字段，Claude Code 会**直接在聊天窗口中渲染一条提示消息**，用户和 Claude 都能看到。

### 适用场景

- 后端 API 调用成功/失败的关键反馈
- Issue 领取/释放等操作结果通知
- 环境检查异常告警

### 配置方式

无需额外配置，在 hook 脚本的 `hook_output()` 中返回即可。

### 代码示例

```bash
#!/bin/bash
# hooks/03-user-prompt-submit/skill-inject.sh 中（示例片段）

# ... 业务逻辑 ...

if _call_backend "/api/issue/claim" "$payload"; then
    hook_output 0 '{"systemMessage": "✅ Issue #12 已成功领取（后端原子领取）"}'
else
    hook_output 0 '{"systemMessage": "⚠️ 后端服务不可用，已降级为标签模式领取"}'
fi
```

### 效果

```
⚠️ 后端服务不可用，已降级为标签模式领取          ← systemMessage 渲染在聊天流中
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 零配置，任何事件都能用 | 只在 hook 触发时显示一次 |
| 直接在对话流中可见 | 不是持久状态，滚屏后消失 |
| 用户和 Claude 都能看到 | 频繁触发会产生过多消息 |

## 机制二：`statusLine` — 持久状态栏（⭐ 推荐方案）

### 原理

Claude Code 支持在界面底部配置一个**持久状态栏**，通过定时执行脚本刷新内容。脚本从 stdin 接收丰富的会话数据（模型名、上下文用量、费用等），输出文本作为状态栏内容。

### 适用场景

- 持久显示后端连接状态
- 显示当前 Session 领取的 Issue 列表
- 显示最近一次 Hook 调用的结果摘要
- 显示活跃 Skill 名称

### 配置方式

在 `.claude/settings.json` 中添加：

```json
{
  "statusLine": {
    "type": "command",
    "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/statusline.sh\"",
    "padding": 2,
    "refreshInterval": 5
  }
}
```

字段说明：
- `command` — 状态栏刷新时执行的脚本
- `padding` — 状态栏内边距（像素）
- `refreshInterval` — 定时刷新间隔（秒），不设则只在每轮对话后刷新

### 架构设计

```
Hook 执行时写状态文件            statusLine.sh 读取并渲染
┌─────────────────┐             ┌──────────────────┐
│ hooks/state/     │   ──读取──→ │ statusline.sh     │
│ ├── backend.stat │             │                   │
│ ├── last_hook.log│             └────────┬──────────┘
│ ├── active_skill │                      │
│ └── issue_claimed│                      ▼
└─────────────────┘             ┌──────────────────┐
                                │ CLI 底部状态栏     │
                                │ ●后端:正常 │已领:#12│
                                └──────────────────┘
```

### 代码示例

**状态栏脚本** `hooks/statusline.sh`：

```bash
#!/bin/bash
# hooks/statusline.sh — 读取状态文件，渲染底部状态栏

STATE_DIR="$CLAUDE_PROJECT_DIR/.claude/hooks/state"

# 读取各模块状态（文件不存在时给默认值）
backend_status=$(cat "$STATE_DIR/backend.status" 2>/dev/null || echo "未知")
last_hook=$(cat "$STATE_DIR/last_hook.log" 2>/dev/null || echo "无")
active_skill=$(cat "$STATE_DIR/active_skill" 2>/dev/null || echo "无")
issue_claimed=$(cat "$STATE_DIR/issue_claimed" 2>/dev/null || echo "无")

# ANSI 颜色定义
GREEN='\033[32m'
YELLOW='\033[33m'
RED='\033[31m'
CYAN='\033[36m'
RESET='\033[0m'

# 后端状态颜色
case "$backend_status" in
    "正常")   color="$GREEN"  ;;
    "不可用") color="$RED"    ;;
    *)        color="$YELLOW" ;;
esac

# 输出状态行（每个 echo 是一行）
echo "${color}● 后端: $backend_status${RESET} | ${CYAN}Skill: $active_skill${RESET} | Issue: $issue_claimed"
echo "最近Hook: $last_hook"
```

**Hook 中写入状态**（在各 hook 脚本中加入）：

```bash
# 在 hooks/base.sh 中添加状态写入函数
write_hook_state() {
    local state_dir="$CLAUDE_PROJECT_DIR/.claude/hooks/state"
    mkdir -p "$state_dir"
    echo "$1" > "$state_dir/last_hook.log"
}

write_backend_state() {
    local state_dir="$CLAUDE_PROJECT_DIR/.claude/hooks/state"
    mkdir -p "$state_dir"
    echo "$1" > "$state_dir/backend.status"
}
```

```bash
# hooks/29-session-end/base.sh 中（示例片段）
# Session 结束时释放 Issue
source "$CLAUDE_PROJECT_DIR/.claude/hooks/base.sh"

write_hook_state "29-session-end: 释放 Issue 中..."

if _call_backend "/api/issue/release-session" "$payload"; then
    write_hook_state "29-session-end: ✅ 已释放所有 Issue"
    write_backend_state "正常"
else
    write_hook_state "29-session-end: ⚠️ 后端不可用，跳过释放"
    write_backend_state "不可用"
fi
```

### 效果（ASCII 模拟）

```
┌─────────────────────────────────────────────────────┐
│  (Claude Code CLI 主聊天区域)                         │
│                                                       │
│  User: /003-4-issue-claim 12                         │
│  Claude: 已领取 Issue #12...                         │
│                                                       │
├─────────────────────────────────────────────────────┤
│  ● 后端: 正常 | Skill: 003-4-issue-claim | Issue: #12│  ← 状态栏
│  最近Hook: 003-4-issue-claim: ✅ 成功领取              │  ← 状态栏第二行
└─────────────────────────────────────────────────────┘
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 持久显示，不随滚屏消失 | 需要额外维护状态文件 |
| 支持定时刷新（`refreshInterval`） | 需要修改多个 hook 脚本写入状态 |
| 支持 ANSI 颜色 | 不影响对话流，Claude 看不到 |
| 支持多行、链接 | 占用底部屏幕空间 |

## 机制三：`statusMessage` — Hook 运行时的旋转提示

### 原理

在 `settings.json` 的 hook 配置中设置 `statusMessage` 字段，Hook **执行期间** CLI 会显示旋转加载动画 + 自定义文字。

### 适用场景

- 后端 API 调用可能耗时较长时提示用户
- Session 初始化时的进度提示
| Issue 领取/释放操作进行中

### 配置方式

在 `.claude/settings.json` 的 hook 配置中添加 `statusMessage`：

```json
{
  "hooks": {
    "PreToolUse": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/05-pre-tool-use/base.sh\"",
            "statusMessage": "🔍 检查工具调用权限..."
          }
        ]
      }
    ],
    "SessionEnd": [
      {
        "matcher": "",
        "hooks": [
          {
            "type": "command",
            "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/29-session-end/base.sh\"",
            "statusMessage": "🔄 正在释放 Session 占用的 Issue..."
          }
        ]
      }
    ]
  }
}
```

### 代码示例

当前项目的 hook 配置改造示例（只改 `settings.json`，不改脚本）：

```json
{
  "hooks": {
    "SessionStart": [

          "statusMessage": "🚀 初始化会话环境..."
        }]
      }
    ],
    "UserPromptSubmit": [
      {
        "matcher": "",
        "hooks": [{
          "type": "command",
          "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/03-user-prompt-submit/base.sh\"",
          "statusMessage": "📋 处理用户输入..."
        }]
      }

    "PreToolUse": [
      {
        "matcher": "",

          "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/05-pre-tool-use/base.sh\"",
          "statusMessage": "🔒 检查工具权限边界..."
        }]
      }
    ],
    "Stop": [
      {
        "matcher": "",
        "hooks": [{
          "type": "command",
          "command": "bash \"$CLAUDE_PROJECT_DIR/.claude/hooks/16-stop/base.sh\"",

    ]
  }
}
```

### 效果

```
⏳ 🔄 正在释放 Session 占用的 Issue...     ← Hook 执行期间显示旋转动画
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 只改配置，不改脚本代码 | 只显示静态文字，不支持动态更新 |
| 用户清楚知道 hook 在执行 | Hook 执行完就消失 |
| 与 loading 动画结合，体验好 | 无法显示执行结果 |

## 机制四：`terminalSequence` — 桌面通知

### 原理

Hook 输出 JSON 中加入 `terminalSequence` 字段，通过终端转义序列触发**系统级桌面通知**或终端铃声。

### 适用场景

- Hook 完成耗时操作后通知用户（即使终端在后台）
- 任务完成提醒（类似现有的 `task-complete-notify.sh`，但走正规 API）
- 错误告警

### 支持的通知协议

| 协议 | 终端软件 |
|------|---------|
| OSC 9 | iTerm2, ConEmu, Windows Terminal, WezTerm |
| OSC 99 | Kitty |
| OSC 777 | urxvt, Ghostty, Warp |

### 代码示例

```bash
#!/bin/bash
# 在 hook 脚本中使用 desktop notification

# Windows Terminal 使用 OSC 9 协议
send_desktop_notify() {
    local title="$1"
    local body="$2"
    # OSC 9 格式: \033]9;<message>\007
    local seq=$(printf '\033]9;%s\007' "${title}: ${body}")
    echo "$seq"
}

# 在 hook 输出中组合使用
hook_output 0 "{\"systemMessage\": \"✅ Issue #12 已领取\", \"terminalSequence\": \"$(send_desktop_notify 'Claude Hook' 'Issue #12 领取成功')\"}"
```

### 终端铃声示例

```bash
# Hook 遇到错误时响铃提醒
hook_output 0 '{"systemMessage": "❌ 后端 API 调用失败", "terminalSequence": "\a"}'
```

### 效果

```
┌──────────────────────────────────────┐
│ 🔔 Claude Hook                       │  ← Windows 系统通知气泡
│ Issue #12 领取成功                    │
└──────────────────────────────────────┘
```

### 优缺点

| 优点 | 缺点 |
|------|------|
| 即使终端在后台也能看到 | 依赖终端软件支持 OSC 协议 |
| 系统级通知，不会被忽略 | Windows Terminal 对 OSC 9 支持有限 |
| 不占用聊天界面空间 | 无法携带复杂内容 |

## 组合使用建议

### 按场景选择机制

| 场景 | 推荐机制 | 理由 |
|------|---------|------|
| 持久显示后端状态、当前 Issue | `statusLine` | 始终可见，定时刷新 |
| 关键操作结果（领取/释放成功） | `systemMessage` | 用户和 Claude 都能看到 |
| 长时间 Hook 执行提示 | `statusMessage` | 执行期间有视觉反馈 |
| Hook 完成后桌面提醒 | `terminalSequence` | 终端在后台也不会错过 |
| Hook 执行错误 | `systemMessage` + `terminalSequence` | 聊天内提示 + 系统通知 |

### 推荐实现优先级

```
阶段 1（最小可行）:
  ├── statusMessage 配置（只改 settings.json，零代码改动）
  └── systemMessage 加入关键 hook（003-4 领取、29 释放）

阶段 2（完整体验）:
  ├── statusLine 脚本 + 状态文件机制
  └── 各 hook 写入状态文件

阶段 3（锦上添花）:
  └── terminalSequence 桌面通知
```

### 完整组合示例

一个 hook 事件同时使用多种机制：

```bash
#!/bin/bash
# hooks/29-session-end/base.sh（改造后片段）

source "$CLAUDE_PROJECT_DIR/.claude/hooks/base.sh"

# ... 业务逻辑 ...

# 写入状态文件（供 statusLine 读取）
write_hook_state "29-session-end: 释放 Issue 中..."

# 调用后端
if _call_backend "/api/issue/release-session" "$payload"; then
    write_hook_state "29-session-end: ✅ 已释放所有 Issue"
    write_backend_state "正常"

    # 组合输出：聊天提示 + 桌面通知
    notify_seq=$(printf '\033]9;Claude Hook: Session 资源已释放\007')
    hook_output 0 "{\"systemMessage\": \"✅ Session 结束，所有 Issue 已释放\", \"terminalSequence\": \"$notify_seq\"}"
else
    write_hook_state "29-session-end: ⚠️ 后端不可用"
    write_backend_state "不可用"

    hook_output 0 '{"systemMessage": "⚠️ 后端不可用，Session Issue 未释放（将在下次启动时清理）"}'
fi
```

## 附录：Hook 输出 JSON 字段速查

| 字段 | 类型 | 作用 | 可用事件 |
|------|------|------|---------|
| `systemMessage` | string | 在聊天界面显示提示消息 | 所有事件 |
| `terminalSequence` | string | 触发终端转义序列（通知/铃声/标题） | 所有事件 |
| `continue` | boolean | `false` 停止 Claude 处理 | 所有事件 |
| `stopReason` | string | `continue=false` 时的提示语 | 所有事件 |
| `suppressOutput` | boolean | `true` 隐藏 hook 输出 | 所有事件 |
| `hookSpecificOutput.permissionDecision` | string | 工具调用许可：`allow/deny/ask/defer` | PreToolUse |
| `hookSpecificOutput.permissionDecisionReason` | string | 许可决定的原因 | PreToolUse |
| `hookSpecificOutput.additionalContext` | string | 注入到 Claude 上下文的额外信息 | PreToolUse, PostToolUse |
| `hookSpecificOutput.updatedInput` | object | 修改工具调用参数 | PreToolUse |
| `hookSpecificOutput.sessionTitle` | string | 设置会话标题 | SessionStart, UserPromptSubmit |
| `decision` | string | `"block"` 阻止操作 | PostToolUse, Stop 等 |
| `reason` | string | 阻止操作的原因 | 同上 |

**statusLine 配置字段：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `command` | string | 状态栏刷新脚本 |
| `padding` | number | 内边距 |
| `refreshInterval` | number | 定时刷新间隔（秒） |

**statusMessage（hook 配置级别）：**

| 字段 | 类型 | 说明 |
|------|------|------|
| `statusMessage` | string | Hook 执行期间显示的旋转提示文字 |
