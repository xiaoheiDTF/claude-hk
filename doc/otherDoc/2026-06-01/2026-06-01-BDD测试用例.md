### 1.1 GET /health 健康检查

```gherkin
Feature: 健康检查
  作为监控服务
  我需要检查后端服务是否正常运行
  以便确认系统可用性

  Background:
    Given 后端服务已启动
    And 数据库连接正常

  @positive
  Scenario: 服务正常运行时返回健康状态
    When 发送 GET 请求到 /health
    Then 响应状态码应为 200
    And 响应体应包含 {"status": "ok"}

  @negative
  Scenario: 服务未启动时无法访问
    Given 后端服务未启动
    When 发送 GET 请求到 /health
    Then 应收到连接拒绝错误
```

### 1.2 POST /api/issue/check 检查 Issue 状态

```gherkin
Feature: 检查 Issue 状态
  作为 AI Agent
  我需要查询指定仓库中 Issue 的当前状态
  以便了解哪些 Issue 可以领取

  Background:
    Given 后端服务已启动
    And 数据库已初始化
    And 存在仓库 "xiaoheiDTF/claude-hk"

  @positive
  Scenario: 查询已存在的 Issue 状态
    Given 仓库 "xiaoheiDTF/claude-hk" 下已存在 Issue #42 状态为 idle
    When 发送 POST 请求到 /api/issue/check
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_numbers": [42]
      }
      """
    Then 响应状态码应为 200
    And 响应体应包含
      """
      {
        "issues": [
          {
            "number": 42,
            "status": "idle",
            "session_id": null,
            "claimed_at": null
          }
        ]
      }
      """

  @positive
  Scenario: 查询不存在的 Issue 自动创建 idle 记录
    Given 仓库 "xiaoheiDTF/claude-hk" 下不存在 Issue #99
    When 发送 POST 请求到 /api/issue/check
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_numbers": [99]
      }
      """
    Then 响应状态码应为 200
    And 响应体中 Issue #99 的状态应为 "idle"
    And 数据库中应存在 Issue #99 的 idle 记录

  @positive
  Scenario: 批量查询多个 Issue 状态
    Given 仓库 "xiaoheiDTF/claude-hk" 下存在以下 Issue:
      | number | status  | session_id |
      | 42     | idle    |            |
      | 45     | claimed | def456     |
      | 38     | fixing  | abc123     |
    When 发送 POST 请求到 /api/issue/check
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_numbers": [42, 45, 38]
      }
      """
    Then 响应状态码应为 200
    And 响应体应返回 3 个 Issue 的状态
    And Issue #42 状态应为 "idle"
    And Issue #45 状态应为 "claimed"
    And Issue #38 状态应为 "fixing"

  @negative
  Scenario: 缺少 repo_full_name 参数
    When 发送 POST 请求到 /api/issue/check
      """
      {
        "issue_numbers": [42]
      }
      """
    Then 响应状态码应为 400
    And 响应体应包含错误码 "invalid_request"

  @negative
  Scenario: 缺少 issue_numbers 参数
    When 发送 POST 请求到 /api/issue/check
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk"
      }
      """
    Then 响应状态码应为 400
    And 响应体应包含错误码 "invalid_request"

  @negative
  Scenario: 使用非 POST 方法请求
    When 发送 GET 请求到 /api/issue/check
    Then 响应状态码应为 405
    And 响应体应包含 "method_not_allowed"
```

### 1.3 POST /api/issue/claim 领取 Issue

```gherkin
Feature: 领取 Issue
  作为 AI Agent
  我需要原子领取指定的 Issue
  以便防止多 Agent 冲突

  Background:
    Given 后端服务已启动
    And 数据库已初始化
    And 存在仓库 "xiaoheiDTF/claude-hk"
    And 存在活跃会话 "session-abc123"

  @positive
  Scenario: 成功领取 idle 状态的 Issue
    Given 仓库 "xiaoheiDTF/claude-hk" 下 Issue #42 状态为 idle
    When 发送 POST 请求到 /api/issue/claim
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_number": 42,
        "session_id": "session-abc123",
        "issue_title": "Fix auth bug"
      }
      """
    Then 响应状态码应为 200
    And 响应体应包含
      """
      {
        "success": true,
        "status": "claimed"
      }
      """
    And 数据库中 Issue #42 的状态应为 claimed
    And 数据库中 Issue #42 的 session_id 应为 "session-abc123"

  @positive
  Scenario: 同一 session 幂等领取
    Given 仓库 "xiaoheiDTF/claude-hk" 下 Issue #42 已被 "session-abc123" 领取
    When 发送 POST 请求到 /api/issue/claim
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_number": 42,
        "session_id": "session-abc123",
        "issue_title": "Fix auth bug"
      }
      """
    Then 响应状态码应为 200
    And 响应体应包含
      """
      {
        "success": true,
        "status": "claimed"
      }
      """

  @negative
  Scenario: Issue 已被其他 session 领取
    Given 仓库 "xiaoheiDTF/claude-hk" 下 Issue #42 已被 "session-def456" 领取
    When 发送 POST 请求到 /api/issue/claim
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_number": 42,
        "session_id": "session-abc123",
        "issue_title": "Fix auth bug"
      }
      """
    Then 响应状态码应为 409
    And 响应体应包含
      """
      {
        "success": false,
        "error": "already_claimed",
        "claimed_by": "session-def456"
      }
      """

  @negative
  Scenario: 缺少必填参数
    When 发送 POST 请求到 /api/issue/claim
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_number": 42
      }
      """
    Then 响应状态码应为 400
    And 响应体应包含错误码 "invalid_request"
```

### 1.4 POST /api/issue/release 释放 Issue

```gherkin
Feature: 释放 Issue
  作为 AI Agent
  我需要释放我持有的 Issue
  以便其他 Agent 可以领取

  Background:
    Given 后端服务已启动
    And 数据库已初始化
    And 存在仓库 "xiaoheiDTF/claude-hk"
    And 存在活跃会话 "session-abc123"

  @positive
  Scenario: 持有者成功释放 Issue
    Given 仓库 "xiaoheiDTF/claude-hk" 下 Issue #42 被 "session-abc123" 领取
    When 发送 POST 请求到 /api/issue/release
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_number": 42,
        "session_id": "session-abc123"
      }
      """
    Then 响应状态码应为 200
    And 响应体应包含
      """
      {
        "success": true,
        "released": true
      }
      """
    And 数据库中 Issue #42 的状态应为 idle
    And 数据库中 Issue #42 的 session_id 应为 null

  @negative
  Scenario: 非持有者无法释放 Issue
    Given 仓库 "xiaoheiDTF/claude-hk" 下 Issue #42 被 "session-def456" 领取
    When 发送 POST 请求到 /api/issue/release
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_number": 42,
        "session_id": "session-abc123"
      }
      """
    Then 响应状态码应为 200
    And 响应体应包含
      """
      {
        "success": false,
        "error": "not_owner"
      }
      """
    And 数据库中 Issue #42 的状态仍为 claimed

  @negative
  Scenario: 终态 Issue 无法释放
    Given 仓库 "xiaoheiDTF/claude-hk" 下 Issue #42 状态为 merged
    And Issue #42 的 session_id 为 "session-abc123"
    When 发送 POST 请求到 /api/issue/release
      """
      {
        "repo_full_name": "xiaoheiDTF/claude-hk",
        "issue_number": 42,
        "session_id": "session-abc123"
      }
      """
    Then 响应状态码应为 200
    And 响应体中 released 应为 false
    And 数据库中 Issue #42 的状态仍为 merged
```
