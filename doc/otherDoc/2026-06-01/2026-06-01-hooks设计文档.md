## 一、系统概述

Hooks 系统是 claude-tap-plus 的核心扩展机制，基于 **Claude Code CLI 的 Hook 协议**实现。通过在 Claude Code 生命周期的关键节点插入 Bash 脚本，实现对 AI 会话的精细化控制、日志记录、后端集成和 Skill 动态加载。

**设计目标**：
- 零侵入：不修改 Claude Code 源码，纯外部扩展
- 事件驱动：29 个生命周期钩子覆盖完整会话流程
- 平台无关：自动适配 Windows/Linux/macOS
- 后端联动：自动注册会话、追踪 Issue 状态
- Skill 生态：支持动态加载和注入自定义能力

## 三、核心模块设计

### 3.1 基础框架 (base.sh)

**职责**：所有 Hook 脚本的公共基础，提供统一的基础设施。

**功能清单**：

| 功能 | 说明 |
|------|------|
| 平台感知 | source `platform.sh`，获取 `OS_TYPE` 和 `PYTHON_CMD` |
| JSON 输入读取 | 从 stdin 读取 Claude Code 传入的 Hook 事件 JSON |
| JSON 字段解析 | `json_get()` 函数，优先 jq，其次 Python，最后 sed fallback |
| 日志记录 | 按日期写入 `logs/YYYY-MM-DD.log`，带时间戳和事件名前缀 |
| 统一输出 | `hook_output()` 函数，记录输出并退出 |
| Skill 分发 | `dispatch_to_skill()` 函数，按事件号分发到对应 Skill 脚本 |

**日志格式**：
```
[2026-06-01 11:19:41] [INFO] [session-start] source=startup
[2026-06-01 11:19:41] [DEBUG] [session-start] os=windows python=python3
```

### 3.2 平台检测 (platform.sh)

**职责**：检测操作系统类型，解析嵌入式或系统 Python 路径。

| 平台 | 检测规则 | Python 路径 |
|------|----------|-------------|
| Linux | `uname -s` = Linux* | `.claude/localLanguage/python/bin/python3` |
| macOS | `uname -s` = Darwin* | `.claude/localLanguage/python/bin/python3` |
| Windows | `uname -s` = MINGW* / MSYS* / CYGWIN* | `.claude/localLanguage/python/python.exe` |

### 3.3 后端调用模块 (lib/backend.sh)

**职责**：封装与 Go 后端服务的 HTTP 通信。

| 函数 | 说明 |
|------|------|
| `_load_backend_url()` | 从 `~/.claude-tap-plus/backend.json` 读取后端地址 |
| `_backend_available()` | 检查后端健康状态（curl `/health`） |
| `_require_backend()` | 强检查：返回 0=可用, 1=不可达, 2=未配置 |
| `_call_backend(endpoint, data)` | POST 调用后端 API，失败静默返回空 |
| `_get_session_id()` | 获取当前 session_id（环境变量或 JSON 解析） |

**后端已提供的只读 API（可被 Hook/状态栏脚本使用）**：

| 端点 | 方法 | 用途 |
|------|------|------|
| `/api/status` | GET | 系统聚合状态（活跃会话、代理、Issue、机器、项目统计） |
| `/api/sessions` | GET | 会话列表（支持按 machine_id/project_slug/status 过滤） |
| `/api/session/{id}/issues` | GET | 会话关联的 Issue 列表 |
| `/api/session/{id}/tokens` | GET | 会话 Token 消耗统计 |
| `/api/session/{id}/traces` | GET | 会话 Trace 文件元数据 |
| `/api/machines` | GET | 机器列表（支持按 os/hostname 过滤） |
| `/api/projects` | GET | 项目列表 |
| `/api/issues` | GET | Issue 列表（支持按 repo/status/session_id 过滤 + 分页） |
| `/api/proxies` | GET | 代理注册列表（支持按 status/project 过滤） |
| `/api/logs` | GET | 后端日志查询（支持按 level/date/limit 过滤） |
| `/api/config` | GET | 获取系统配置 |
| `/api/config` | PUT | 更新系统配置 |

**配置读取 (config.sh)**：
```bash
# ~/.claude-tap-plus/backend.json
{
  "host": "127.0.0.1",
  "port": 8080
}
```

### 4.2 关键事件详细设计

#### 01-session-start（会话初始化）

**执行流程**：
```
1. 首次运行检查 → 触发 .claude/init.sh 统一初始化
2. UTF-8 编码设置（Windows 设置 code page 65001）
3. Python 可用性检查 → 自动修复
4. 目录完整性检查 → 自动创建缺失目录
5. Skill 级巡检 → 执行各 Skill 的 init_check.sh
6. Trace 路径初始化 → 通过后端转发到代理
7. 后端会话注册 → POST /api/session/register
```

**向后端发送的数据**：
```json
{
  "session_id": "uuid",
  "machine_id": "whoami@hostname",
  "os": "windows|linux|macos",
  "project_slug": "从 transcript_path 解析",
  "project_cwd": "当前工作目录",
  "transcript_path": "Claude Code 对话记录路径",
  "model": "使用的模型",
  "source": "startup|resume"
}
```

#### 03-user-prompt-submit（Skill 注入）

**执行流程**：
```
1. 提取用户 prompt 和 session_id
2. 调用 skill-inject.sh 解析 /xxx 格式
3. 匹配 registry.conf 注册表
4. 执行 Skill 的 03UserPromptSubmit.sh 获取上下文
5. 写入 .active 文件（session_id|skill_name）
6. 输出上下文 JSON 供 Claude Code 使用
```

**Skill 调用语法**：
```
/skill-name args...    # 首字符必须是 /
```

#### 05-pre-tool-use（权限控制）

**双层拦截设计**：

| 层级 | 脚本 | 作用域 | 说明 |
|------|------|--------|------|
| A 层 | `skills/enforce_boundary.sh` | 全局 | 工具级白名单拦截（在 dispatch 之前执行） |
| B 层 | Skill 的 `05PreToolUse.sh` | 按需 | 路径级精细拦截 |

**权限决策优先级**：`deny > defer > ask > allow`

#### 16-stop（Skill 注册与激活）

**执行流程**：
```
1. 执行 skill-register.sh → 扫描新增 Skill 写入 registry.conf
2. 从 .active 获取当前 session 激活的 Skill
3. 执行该 Skill 的 16Stop.sh（如存在）
4. Windows：调用 task-complete-notify.sh 前置窗口
```

#### 29-session-end（会话清理）

**执行流程**：
```
1. Skill 分发（29SessionEnd.sh）
2. 释放该 session 持有的所有非终态 Issue
   → POST /api/issue/release-session
3. 注销后端会话
   → POST /api/session/close
```

|------|------|------|
| 添加/更新 | `active_add(sid, skill_name)` | 幂等，同 session 不重复 |

## 六、Windows 特殊功能

### 6.1 窗口前置系统

**触发时机**：
- `06-permission-request`：权限对话框出现时前置终端
- `16-stop`：Claude 完成响应时前置终端

**实现方案**：
```
Bash (hooks) → PowerShell (win32-foreground.ps1) → Win32 API
```

**PowerShell 脚本功能**：
1. 遍历进程树查找终端进程（WindowsTerminal / ConEmu64 / cmder）
2. 枚举窗口，按标题 hint 匹配最佳窗口
3. 禁用 Windows 前台锁定（SystemParametersInfo）
4. 多策略前置：Alt 键 trick → COM AppActivate → SetForegroundWindow
5. 临时置顶 1 秒确保可见
6. 任务栏闪烁 + 系统提示音
7. 恢复原始前台锁定超时

## 七、与后端的交互流程

### 7.1 会话生命周期

```
[01-session-start]
    │
    ├──► POST /api/proxy/trace-init  →  初始化 trace 路径
    │
    └──► POST /api/session/register  →  注册会话到后端
              │
              ▼
        [会话进行中... Issue 领取/状态更新]
              │
              ▼
        [可随时查询]
              │
              ├──► GET /api/status   →  查询系统聚合状态（供前端/状态栏使用）
              ├──► GET /api/proxies  →  查询代理注册列表
              ├──► GET /api/sessions →  查询会话列表
              ├──► GET /api/machines →  查询机器列表
              ├──► GET /api/projects →  查询项目列表
              ├──► GET /api/issues   →  查询 Issue 列表（支持过滤+分页）
              ├──► GET /api/session/{id}/tokens   →  查询会话 Token 统计
              ├──► GET /api/session/{id}/traces    →  查询会话 Trace 文件
              ├──► GET /api/session/{id}/issues    →  查询会话关联 Issue
              ├──► GET /api/logs     →  查询后端日志
              ├──► GET /api/config   →  查询系统配置
              └──► PUT /api/config   →  更新系统配置
              │
              ▼
[29-session-end]
    │
    ├──► POST /api/issue/release-session  →  释放该会话所有 Issue
    │
    └──► POST /api/session/close  →  注销会话
```

### 7.2 Issue 工作流（通过 Skill 触发）

```
用户: /issue-claim 123
    │
    ▼
03-user-prompt-submit → skill-inject.sh
    │
    ▼
激活 issue-claim Skill
    │
    ▼
Claude 执行 claim 逻辑
    │
    ▼
调用后端: POST /api/issue/claim
    │
    ▼
后续状态更新: POST /api/issue/status
```

## 九、扩展设计建议

### 9.1 新增 Hook 事件

当前 29 个事件已覆盖 Claude Code 完整生命周期，如需扩展可考虑：

| 建议事件 | 触发时机 | 用途 |
|----------|----------|------|
| `pre-model-call` | 发送请求给模型前 | 记录/修改 prompt |
| `post-model-response` | 收到模型响应后 | 记录/审查响应 |
| `tool-timeout` | 工具调用超时时 | 自动重试或降级 |
| `rate-limit` | 触发速率限制时 | 自动退避 |

### 9.2 Hook 性能优化

| 优化点 | 方案 |
|--------|------|
| 减少后端调用 | 批量聚合多次 API 调用 |
| 异步日志 | 日志写入改为后台进程 |
| Skill 缓存 | 已加载的 Skill 脚本缓存到内存 |
| 条件触发 | 根据配置选择性启用 Hook |

### 9.3 安全增强

| 增强点 | 方案 |
|--------|------|
| 命令审计 | 05-pre-tool-use 中记录所有 Bash 命令 |
| 敏感词过滤 | 03-user-prompt-submit 中检测敏感操作 |
| 沙箱检测 | 检测是否在隔离环境中运行 |
| 网络白名单 | 限制后端仅允许本地连接 |
