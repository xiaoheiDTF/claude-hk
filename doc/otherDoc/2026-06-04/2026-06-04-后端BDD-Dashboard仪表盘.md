## 场景生成规则

本节列出后端场景的思考规则，用于引导场景的发现和拆解。规则不是限制——不是"只能写这些"，而是"沿着这些方向想"。

### 规则 1：从 BDD 场景推导后端行为

每条 BDD 场景描述了用户的行为，后端需要提供功能接口来支撑这个行为。一个 BDD 场景可能涉及多个后端功能接口，每个接口的每种条件组合各写一条后端场景。

### 规则 2：从实体的属性和生命周期推导数据前提

实体有什么属性、属性之间有什么关联、实体从创建到消亡经历哪些状态——这些都是后端场景的数据前提。实体之间的引用关系（Issue 引用 Session、Session 引用 Machine）是跨实体一致性场景的来源。

### 规则 3：从边界条件推导后端极端行为

功能点的每条边界条件，在后端都有对应的极端表现：数据为空、数据量极大、状态处于临界值。这些不是前端独有的，后端同样需要处理。

### 规则 4：后端独有关注点作为补充

以下关注点是 BDD 场景阶段不会覆盖的，后端 BDD 必须主动考虑：

- **并发安全** — 多个请求同时到达同一接口
- **竞态条件** — 读写同时发生，数据是否一致
- **资源争抢** — 数据库锁竞争、连接池耗尽
- **实体状态机转换** — 实体能否从一个状态合法跳到另一个状态
- **跨实体一致性** — 一个实体的变更是否影响关联实体的一致性
- **数据完整性** — 引用关联失效时的行为
- **部分失败** — 多步骤操作中某步失败，是回滚还是降级

## 功能接口 1：系统状态统计

返回系统五项核心统计：活跃会话数、待处理 Issue 数、活跃代理数、机器总数、项目总数。

### 正向场景

**B1-01：系统中有正常数据时查询统计**

| 项目 | 内容 |
|------|------|
| 数据前提 | 系统中有 3 条活跃会话、5 条待处理 Issue（idle）、2 个活跃代理、4 台机器、3 个项目 |
| 功能接口 | 系统状态统计 |
| 预期结果 | 返回成功，包含：活跃会话 3、待处理 Issue 5、活跃代理 2、机器总数 4、项目总数 3 |
| 规则来源 | 规则 1（← F1-S1） |

### 异常场景

**B1-02：查询过程中数据库不可用**

| 项目 | 内容 |
|------|------|
| 数据前提 | 系统正常运行，数据库突然不可用 |
| 功能接口 | 系统状态统计 |
| 预期结果 | 返回错误，告知调用方查询失败；不返回部分数据（不出现 3 项成功 2 项失败的中间态） |
| 规则来源 | 规则 1（← F1-S2）+ 规则 4（部分失败） |

**B1-03：五项统计中部分子查询超时**

| 项目 | 内容 |
|------|------|
| 数据前提 | 系统中数据量较大（会话 500 条、Issue 2000 条），会话计数查询超时，其余四项正常 |
| 功能接口 | 系统状态统计 |
| 预期结果 | 返回错误，整体失败；不返回"活跃会话: 错误，其余正常"的混合结果 |
| 规则来源 | 规则 4（部分失败） |

### 边界场景

**B1-04：系统中无任何数据**

| 项目 | 内容 |
|------|------|
| 数据前提 | 数据库已初始化，无任何会话、Issue、代理、机器、项目记录 |
| 功能接口 | 系统状态统计 |
| 预期结果 | 返回成功，五项统计均为 0 |
| 规则来源 | 规则 3（← F1-S4） |

**B1-05：某类记录超过 999 条**

| 项目 | 内容 |
|------|------|
| 数据前提 | 系统中有 1200 条 Issue（全部 merged），活跃会话 5、活跃代理 2、机器 3、项目 2 |
| 功能接口 | 系统状态统计 |
| 预期结果 | 返回成功，待处理 Issue 为 0（idle），机器 3，项目 2；数值正确不截断 |
| 规则来源 | 规则 3（← F1-S5） |

**B1-06：数据变更后再次查询**

| 项目 | 内容 |
|------|------|
| 数据前提 | 活跃会话 3、待处理 Issue 5；第一次查询后，新注册 2 条会话，3 条 Issue 从 idle 变为 claimed |
| 功能接口 | 系统状态统计（第二次调用） |
| 预期结果 | 返回活跃会话 5、待处理 Issue 2，反映最新数据 |
| 规则来源 | 规则 1（← F1-S6） |

**B1-07：多个客户端同时查询统计**

| 项目 | 内容 |
|------|------|
| 数据前提 | 活跃会话 10、活跃代理 3，数据不变 |
| 功能接口 | 系统状态统计（10 个并发调用） |
| 预期结果 | 10 次调用全部返回成功且结果一致（活跃会话 10、活跃代理 3），无并发错误 |
| 规则来源 | 规则 4（并发安全） |

**B1-08：查询统计的同时有新会话注册**

| 项目 | 内容 |
|------|------|
| 数据前提 | 活跃会话 5 |
| 功能接口 | 系统状态统计（与 1 条新会话注册同时发生） |
| 预期结果 | 统计返回成功，活跃会话为 5 或 6（取决于注册是否先完成），不返回错误或不一致数据 |
| 规则来源 | 规则 4（竞态条件） |

## 功能接口 2：会话列表查询

返回按时间倒序排列的会话列表，包含会话标识、来源机器、所属项目、状态、注册时间。

### 正向场景

**B2-01：系统中有多种状态的会话**

| 项目 | 内容 |
|------|------|
| 数据前提 | 4 条会话：A（active，project-x，user@host-1，14:32）、B（active，project-y，user@host-2，14:28）、C（closed，project-x，user@host-1，14:15）、D（active，project-z，user@host-3，14:10） |
| 功能接口 | 会话列表查询 |
| 预期结果 | 返回成功，4 条记录按注册时间倒序：A → B → C → D；每条包含会话标识、机器、项目、状态、注册时间 |
| 规则来源 | 规则 1（← F2-S1） |

### 异常场景

**B2-02：查询过程中数据库不可用**

| 项目 | 内容 |
|------|------|
| 数据前提 | 系统正常运行，数据库突然不可用 |
| 功能接口 | 会话列表查询 |
| 预期结果 | 返回错误，告知调用方查询失败；不返回空列表（空列表 = "无数据"，与"查询失败"含义不同） |
| 规则来源 | 规则 1（← F2-S2） |

**B2-03：会话数据中存在引用失效的机器记录**

| 项目 | 内容 |
|------|------|
| 数据前提 | 会话记录中 machine_id 为 "ghost@host-99"，但 machines 表中不存在该记录 |
| 功能接口 | 会话列表查询 |
| 预期结果 | 返回成功，该条会话正常返回，machine_id 字段为 "ghost@host-99"；不因引用失效而报错或跳过该记录 |
| 规则来源 | 规则 4（数据完整性） |

### 边界场景

**B2-04：系统中无任何会话**

| 项目 | 内容 |

| 规则来源 | 规则 3（← F2-S3） |

**B2-05：系统中仅有 1 条会话**

| 项目 | 内容 |

| 功能接口 | 会话列表查询 |
| 预期结果 | 返回成功，1 条记录，内容完整 |
| 规则来源 | 规则 3（← F2-S4） |

**B2-06：会话数量超过默认分页上限**

| 项目 | 内容 |
|------|------|
