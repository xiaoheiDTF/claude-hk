# 功能点分析：Dashboard 仪表盘

> 文档日期：2026-06-04
> 输入来源：Dashboard 页面线框图
> 阶段定位：功能点与功能树，明确仪表盘要做什么

---

## 一、功能描述

用户需要一个仪表盘页面，作为 Claude Tap Plus Web UI 的首页。用户打开页面后，能够一目了然地看到系统当前运行状态的全貌——有多少会话在跑、有多少 Issue 待处理、有多少代理在线、接入了多少台机器和项目。同时能快速浏览最近的会话活动，以及 Issue 在各状态上的分布情况。

---

## 二、功能点列表

### F1: 统计概览（Stats Cards）

**做什么：** 用户以卡片形式查看系统五项核心统计数字——活跃会话数、待处理 Issue 数、活跃代理数、机器总数、项目总数。

**涉及谁：** 会话、Issue、代理、机器、项目

**什么情况下不一样：**

| # | 边界场景 | 可测试验证 |
|---|---------|-----------|
| B1-1 | 系统刚启动，所有统计均为 0 | 五张卡片均显示数字 0，无报错 |
| B1-2 | 某项统计数字超过 999 | 数字正常显示，卡片布局不被撑破 |
| B1-3 | 后端服务未启动或不可达 | 卡片显示错误状态（如 "—" 或错误提示），而非空白或卡死 |
| B1-4 | 后端返回延迟超过 5 秒 | 页面显示加载状态，最终超时后提示用户 |
| B1-5 | 数字实时变化（新会话注册、Issue 被领取） | 卡片数字在刷新后更新，不累积旧数据 |

### F2: 最近会话活动（Recent Sessions）

**做什么：** 用户查看按时间倒序排列的最近会话列表，了解每个会话的状态、发生时间、所属项目、来源机器、当前状态。

**涉及谁：** 会话

**什么情况下不一样：**

| # | 边界场景 | 可测试验证 |
|---|---------|-----------|
| B2-1 | 系统中无任何会话 | 列表区域显示空状态提示（如 "暂无会话"），而非空白 |
| B2-2 | 系统中仅有 1 条会话 | 列表显示 1 条记录，布局正常 |
| B2-3 | 会话数超过列表可显示区域（如超过 20 条） | 列表截断显示（如最近 N 条），或提供分页/滚动，不一次性加载全部 |
| B2-4 | 所有会话均为 active 状态 | 列表全部显示绿色状态标识，无 closed 记录 |
| B2-5 | 所有会话均为 closed 状态 | 列表全部显示红色状态标识，无 active 记录 |
| B2-6 | 同一机器上有多条会话 | 列表正常显示，用户能识别同一来源的多条记录 |
| B2-7 | 同一项目下有多条会话 | 列表正常显示，项目名重复出现不影响阅读 |
| B2-8 | 会话 ID 过长（完整 UUID） | ID 截断显示（如前 6 位 + "..."），不撑破列宽 |
| B2-9 | 会话刚注册（registered_at 为当前秒） | 时间列正常显示，不出现未来时间或空白 |

### F3: Issue 状态分布（Issue Status Distribution）

**做什么：** 用户查看 Issue 在各状态上的数量分布，快速了解整体 Issue 处理进度。

**涉及谁：** Issue

**什么情况下不一样：**

| # | 边界场景 | 可测试验证 |
|---|---------|-----------|
| B3-1 | 系统中无任何 Issue | 分布区域显示空状态提示，各状态计数均为 0 |
| B3-2 | 所有 Issue 处于同一状态 | 该状态显示全部数量，其余状态为 0 |
| B3-3 | Issue 覆盖了所有 8 种状态 | 8 种状态全部展示，布局不被撑破 |
| B3-4 | 某一状态数量远超其他（如 merged: 500，其余均 < 5） | 最大值不撑破布局，小值仍可辨识 |
| B3-5 | Issue 状态频繁变化（测试中状态流转） | 刷新后分布数字更新，不累积旧数据 |
| B3-6 | 只有一种状态有 Issue，其余为 0 | 分布只展示有值的状态，或全部展示但零值状态明确标记 |

## 三、实体列表

### 3.1 会话（Session）

- **属性：** 会话标识、来源机器、所属项目、工作目录、状态（active / closed）、注册时间、关闭时间
- **生命周期：** 注册（active） → 关闭（closed）
- **删除影响：** 无法追踪哪些 Claude 实例正在运行或曾经运行过
- **参与功能：** F1（统计计数）、F2（活动列表）

### 3.2 Issue

- **属性：** 所属仓库、Issue 编号、标题、当前状态（idle / claimed / fixing / ready-for-pr / pr-created / testing / reviewing / merged / rejected）、领取会话、领取时间
- **生命周期：** 创建（idle） → 领取（claimed） → 修复（fixing） → 完成 → PR → 测试 → 审核 → 合并（merged）或打回（rejected）
- **删除影响：** 无法追踪 Issue 的工作流状态和领取情况
- **参与功能：** F1（待处理计数）、F3（状态分布）

### 3.3 代理（Proxy）

- **属性：** 代理标识、所属项目、状态（active / inactive）、注册时间、最近心跳时间
- **生命周期：** 注册（active） → 注销（inactive）
- **删除影响：** 无法得知有多少代理实例在线
- **参与功能：** F1（活跃代理计数）

### 3.4 机器（Machine）

- **属性：** 机器标识（用户名@主机名）、操作系统、主机名、用户名、首次发现时间、最近发现时间
- **生命周期：** 首次连接 → 持续活跃
- **删除影响：** 无法得知系统覆盖了多少台物理机
- **参与功能：** F1（机器总数计数）

### 3.5 项目（Project）

- **属性：** 项目标识、工作目录路径、首次发现时间、最近发现时间
- **生命周期：** 首次连接 → 持续活跃
- **删除影响：** 无法得知系统管理了多少个项目
- **参与功能：** F1（项目总数计数）

## 四、功能定位

| 属性 | 值 |
|------|-----|
| 所属模块 | Web UI — Dashboard 页面 |
| 与现有功能关联 | 消费后端已有的 `GET /api/status`、`GET /api/sessions`、`GET /api/issues` 接口数据 |
| 功能类型 | **新增** — 前端仪表盘页面，后端接口已存在或已在 BDD-TDD 系列中定义 |

## 五、完整性检查

### 5.1 粒度检查

- F1 统计概览：用户意图是"一眼看系统状态" → 粒度合适
- F2 最近会话：用户意图是"快速浏览最近在发生什么" → 粒度合适
- F3 Issue 分布：用户意图是"了解 Issue 处理进度" → 粒度合适

### 5.2 遗漏检查

模拟用户旅程：用户打开页面 → 看到 5 个统计数字（F1）→ 目光下移看到最近会话列表（F2）→ 再下移看到 Issue 分布（F3）→ 想了解更多，点击左侧导航进入子页面。

发现：线框图中左侧导航栏包含 📊 Dashboard、🖥️、📋 三个入口，但导航行为属于整体布局功能，不属于 Dashboard 功能点的范畴。Dashboard 页面本身的功能点已完整覆盖。

### 5.3 冲突检查

- F1 的"待处理 Issue 数"与 F3 的 Issue 分布存在数据重叠（F1 取 idle 状态计数，F3 取全部状态计数），但展示目的不同（概览数字 vs 分布详情），不构成冲突。
