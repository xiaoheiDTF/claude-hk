## F1: 统计概览（Stats Cards）

### 正向场景

**F1-S1：用户打开仪表盘，系统有正常数据**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 3 条活跃会话、5 条待处理 Issue（idle 状态）、2 个活跃代理、4 台机器、3 个项目 |
| 动作 | 用户打开仪表盘页面 |
| 预期 | 页面顶部显示 5 张卡片，分别展示：活跃会话 3、待处理 Issue 5、活跃代理 2、机器总数 4、项目总数 3 |
| 追溯 | F1 功能描述 |

### 异常场景

**F1-S2：后端服务未启动，用户打开仪表盘**

| 项目 | 内容 |
|------|------|
| 前提 | 后端服务未启动，无法连接 |
| 动作 | 用户打开仪表盘页面 |
| 预期 | 5 张卡片不显示空白或卡死，每张卡片展示错误状态标识（如 "—"），用户能感知到数据加载失败 |
| 追溯 | B1-3 |

**F1-S3：后端响应缓慢，用户等待超时**

| 项目 | 内容 |
|------|------|
| 前提 | 后端服务运行中，但响应延迟超过 5 秒 |
| 动作 | 用户打开仪表盘页面 |
| 预期 | 页面先显示加载状态（如加载动画），等待超时后提示用户加载失败或数据暂时不可用 |
| 追溯 | B1-4 |

### 边界场景

**F1-S4：系统刚启动，所有统计均为 0**

| 项目 | 内容 |
|------|------|
| 前提 | 系统刚完成首次启动，无任何会话、Issue、代理、机器、项目数据 |
| 动作 | 用户打开仪表盘页面 |
| 预期 | 5 张卡片均显示数字 0，卡片布局正常，无报错或异常 |
| 追溯 | B1-1 |

**F1-S5：某项统计数字超过 999**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 1200 条已合并的 Issue（merged 状态），其他统计正常（活跃会话 5、活跃代理 2、机器 3、项目 2） |
| 动作 | 用户打开仪表盘页面 |
| 预期 | 5 张卡片均正常显示，数字 "1200" 不撑破卡片宽度，卡片间布局不受影响 |
| 追溯 | B1-2 |

**F1-S6：后台数据发生变化后刷新页面**

| 项目 | 内容 |
|------|------|
| 前提 | 页面显示活跃会话 3、待处理 Issue 5 |
| 动作 | 另一个用户注册了 2 条新会话、领取了 3 条 Issue；当前用户刷新页面 |
| 预期 | 卡片更新为活跃会话 5、待处理 Issue 2，数字反映最新状态，不保留旧数据 |
| 追溯 | B1-5 |

## F2: 最近会话活动（Recent Sessions）

### 正向场景

**F2-S1：用户查看最近会话列表，有多条不同状态的记录**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 4 条会话：会话 A（active，project-x，user@host-1，14:32）、会话 B（active，project-y，user@host-2，14:28）、会话 C（closed，project-x，user@host-1，14:15）、会话 D（active，project-z，user@host-3，14:10） |
| 动作 | 用户打开仪表盘页面，查看"最近会话活动"区域 |
| 预期 | 列表按时间倒序显示 4 条记录：A（绿色标识）、B（绿色标识）、C（红色标识）、D（绿色标识），每条记录展示时间、会话 ID（截断）、项目名、机器名、状态 |
| 追溯 | F2 功能描述 |

### 异常场景

**F2-S2：会话数据加载失败**

| 项目 | 内容 |
|------|------|
| 前提 | 后端服务不可达 |
| 动作 | 用户打开仪表盘页面，查看"最近会话活动"区域 |
| 预期 | 列表区域不显示空白或卡死，展示加载失败提示信息 |
| 追溯 | B1-3（与 F1 共享同一后端依赖） |

### 边界场景

**F2-S3：系统中无任何会话**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中没有任何会话记录 |
| 动作 | 用户查看"最近会话活动"区域 |
| 预期 | 列表区域显示空状态提示（如 "暂无会话记录"），而非空白区域 |
| 追溯 | B2-1 |

**F2-S4：系统中仅有 1 条会话**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中只有 1 条会话（active，project-x，user@host-1，14:32） |
| 动作 | 用户查看"最近会话活动"区域 |
| 预期 | 列表显示 1 条记录，布局完整，时间、项目、机器、状态均正常展示 |
| 追溯 | B2-2 |

**F2-S5：会话数量超过列表默认显示上限**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 50 条会话记录 |
| 动作 | 用户查看"最近会话活动"区域 |
| 预期 | 列表只显示最近的 N 条（如 20 条），可通过滚动或分页查看更多，不会一次性加载全部 50 条 |
| 追溯 | B2-3 |

**F2-S6：所有会话均为 active 状态**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 5 条会话，全部为 active 状态 |
| 动作 | 用户查看"最近会话活动"区域 |
| 预期 | 列表 5 条记录全部显示绿色状态标识，无红色标识出现 |
| 追溯 | B2-4 |

**F2-S7：所有会话均为 closed 状态**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 5 条会话，全部为 closed 状态 |
| 动作 | 用户查看"最近会话活动"区域 |
| 预期 | 列表 5 条记录全部显示红色状态标识，无绿色标识出现 |
| 追溯 | B2-5 |

**F2-S8：同一机器上有多条会话**

| 项目 | 内容 |
|------|------|
| 前提 | 机器 user@host-1 上有 3 条会话（2 条 active、1 条 closed），分别属于 project-x 和 project-y |
| 动作 | 用户查看"最近会话活动"区域 |
| 预期 | 列表正常显示 3 条记录，机器列均显示 "user@host-1"，用户能通过项目列区分这 3 条记录 |
| 追溯 | B2-6 |

**F2-S9：会话 ID 过长（完整 UUID）**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中 1 条会话，会话 ID 为 `abc123def456-7890-ghij-klmn-opqrstuvwxyz` |
| 动作 | 用户查看"最近会话活动"区域 |
| 预期 | 会话 ID 截断显示（如 "abc123..."），不撑破列宽，列表布局保持正常 |
| 追溯 | B2-8 |

**F2-S10：会话刚注册，时间为当前时刻**

| 项目 | 内容 |
|------|------|
| 前提 | 用户刚刚触发了一个新会话注册，该会话的注册时间为当前分钟 |
| 动作 | 用户立即查看"最近会话活动"区域 |
| 预期 | 该条记录出现在列表顶部，时间列显示当前时间（非未来时间、非空白） |
| 追溯 | B2-9 |

## F3: Issue 状态分布（Issue Status Distribution）

### 正向场景

**F3-S1：用户查看 Issue 状态分布，有多种状态的 Issue**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 20 条 Issue：idle 8 条、claimed 3 条、fixing 2 条、testing 1 条、merged 6 条 |
| 动作 | 用户查看"Issue 状态分布"区域 |
| 预期 | 分布展示 5 种状态及对应数量：idle: 8、claimed: 3、fixing: 2、testing: 1、merged: 6，各状态之间有视觉分隔 |
| 追溯 | F3 功能描述 |

### 异常场景

**F3-S2：Issue 数据加载失败**

| 项目 | 内容 |
|------|------|
| 前提 | 后端服务不可达 |
| 动作 | 用户查看"Issue 状态分布"区域 |
| 预期 | 分布区域不显示空白或卡死，展示加载失败提示信息 |
| 追溯 | B1-3（与 F1 共享同一后端依赖） |

### 边界场景

**F3-S3：系统中无任何 Issue**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中没有任何 Issue 记录 |
| 动作 | 用户查看"Issue 状态分布"区域 |
| 预期 | 分布区域显示空状态提示（如 "暂无 Issue"），各状态计数为 0 或不展示 |
| 追溯 | B3-1 |

**F3-S4：所有 Issue 处于同一状态**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 15 条 Issue，全部为 merged 状态 |
| 动作 | 用户查看"Issue 状态分布"区域 |
| 预期 | merged 状态显示 15，其余状态显示 0 或不展示；只有 merged 有实际数值 |
| 追溯 | B3-2、B3-6 |

**F3-S5：Issue 覆盖了所有 8 种状态**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 Issue 覆盖全部状态：idle 2、claimed 2、fixing 2、ready-for-pr 1、pr-created 1、testing 1、reviewing 1、merged 3 |
| 动作 | 用户查看"Issue 状态分布"区域 |
| 预期 | 8 种状态全部展示，布局不被撑破，每个状态的数值均可辨识 |
| 追溯 | B3-3 |

**F3-S6：某一状态数量远超其他状态**

| 项目 | 内容 |
|------|------|
| 前提 | 系统中有 500 条 merged Issue，其余状态各 1 条（idle 1、claimed 1、fixing 1） |
| 动作 | 用户查看"Issue 状态分布"区域 |
| 预期 | merged: 500 正常展示不撑破布局，idle/claimed/fixing 各 1 的数值仍然可辨识，不被视觉吞没 |
| 追溯 | B3-4 |

**F3-S7：Issue 状态发生变化后刷新页面**

| 项目 | 内容 |
|------|------|
| 前提 | 页面当前显示 idle: 8、claimed: 3 |
| 动作 | 有 2 条 idle Issue 被领取变为 claimed；当前用户刷新页面 |
| 预期 | 分布更新为 idle: 6、claimed: 5，数字反映最新状态，不保留旧数据 |
| 追溯 | B3-5 |

## 完整性检查

### 覆盖检查

- F1：正向 1 + 异常 2 + 边界 3 = 6 条 ✓
- F2：正向 1 + 异常 1 + 边界 7 = 9 条 ✓
- F3：正向 1 + 异常 1 + 边界 5 = 7 条 ✓
- 每个功能点均覆盖正向/异常/边界三种类型 ✓

### 重复检查

- F2-S6（全部 active）与 F2-S7（全部 closed）是不同前提的不同场景，非重复 ✓
- F3-S4 同时覆盖 B3-2 和 B3-6，因前提和预期结果一致，合并为一条场景 ✓

### 冲突检查

- F1-S6（刷新后数字更新）与 F3-S7（刷新后分布更新）描述的是同一用户动作作用于不同区域，预期结果不矛盾 ✓
