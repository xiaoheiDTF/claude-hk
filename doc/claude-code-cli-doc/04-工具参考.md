## Bash 工具行为技巧

### 工作目录持久化
- 当 Claude 在主会话中运行 `cd` 时，只要它保持在项目目录内或使用 `--add-dir`、 `/add-dir` 或设置中的 `additionalDirectories` 添加的额外工作目录内，新的工作目录就会延续到后续的 Bash 命令
- 如果 `cd` 落在这些目录之外，Claude Code 会重置为项目目录，并将 `Shell cwd was reset to <dir>` 附加到工具结果
- **技巧**：要禁用此延续，使每个 Bash 命令都在项目目录中启动，请设置 `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR=1`

### 环境变量
- 环境变量不持久。一个命令中的 `export` 在下一个命令中将不可用
- **技巧**：在启动 Claude Code 之前激活您的 virtualenv 或 conda 环境。要使环境变量在 Bash 命令之间保持不变，请将 `CLAUDE_ENV_FILE` 设置为 shell 脚本，或使用 SessionStart hook 动态填充它

## LSP 工具行为技巧

LSP 工具为 Claude 提供来自运行中的语言服务器的代码智能。在每次文件编辑后，它会自动报告类型错误和警告。

### LSP 工具功能
- 跳转到符号的定义
- 查找对符号的所有引用
- 获取位置处的类型信息
- 列出文件或工作区中的符号
- 查找接口的实现
- 追踪调用层次结构

### 使用技巧
- 该工具在您为您的语言安装 code intelligence plugin 之前处于非活动状态
- 该插件捆绑了语言服务器配置，您需要单独安装服务器二进制文件

## Monitor 工具技巧

Monitor 工具让 Claude 在后台监视某些内容，并在其更改时做出反应，而无需暂停对话。

### 常见用例
- 跟踪日志文件并在错误出现时标记它们
- 轮询 PR 或 CI 作业并在其状态更改时报告
- 监视目录以查找文件更改
- 跟踪任何长时间运行脚本的输出

### 工作原理
Claude 为监视编写一个小脚本，在后台运行它，并在每行到达时接收它。您可以在同一会话中继续工作，Claude 在事件到达时插入。

### 使用技巧
- 通过要求 Claude 取消它或结束会话来停止监视
- Monitor 使用与 Bash 相同的权限规则
- 它在 Amazon Bedrock、Google Vertex AI 或 Microsoft Foundry 上不可用
- 当设置了 `DISABLE_TELEMETRY` 或 `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` 时，它也不可用
- 插件可以声明在插件处于活动状态时自动启动的监视，而不是要求 Claude 启动它们

## PowerShell 工具技巧

PowerShell 工具让 Claude 本地运行 PowerShell 命令。

### 启用 PowerShell 工具
在您的环境或 `settings.json` 中设置 `CLAUDE_CODE_USE_POWERSHELL_TOOL=1`：

```json
{
  "env": {
    "CLAUDE_CODE_USE_POWERSHELL_TOOL": "1"
  }
}
```

### 平台差异
- **无 Git Bash 的 Windows**：该工具会自动启用；设置为 `0` 以禁用它
- **有 Git Bash 的 Windows**：该工具正在逐步推出：设置为 `1` 以选择加入或 `0` 以选择退出
- **Linux、macOS 和 WSL**：设置为 `1` 以启用它，这需要您的 `PATH` 上有 `pwsh`
- **Windows**：Claude Code 自动检测 `pwsh.exe`（PowerShell 7+），回退到 `powershell.exe`（PowerShell 5.1）

### Shell 选择配置
- `settings.json` 中的 `"defaultShell": "powershell"`：通过 PowerShell 路由交互式 `!` 命令
- 单个 command hooks 上的 `"shell": "powershell"`：在 PowerShell 中运行该 hook
- skill frontmatter 中的 `shell: powershell`：在 PowerShell 中运行 ``!`command` `` 块

### 预览限制
- PowerShell 配置文件未加载
- 在 Windows 上，不支持 sandboxing

## 检查工具可用性

您的确切工具集取决于您的提供商、平台和设置。要检查在运行中的会话中加载了什么：

1. 直接询问 Claude：`What tools do you have access to?`
2. 对于确切的 MCP 工具名称，请运行 `/mcp`
