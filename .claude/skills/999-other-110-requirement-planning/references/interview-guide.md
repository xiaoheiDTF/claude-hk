# 关键信息澄清指南

文档生成前，对缺少的关键信息做最小化澄清。

## 澄清原则

1. **只问影响文档生成的问题** — 不做完整访谈
2. **逐个提问** — 每次只问一个，等待回答后再问下一个
3. **使用 AskUserQuestion** — 提供可点击选项，不要求用户手工录入
4. **信息足够就生成** — 不追求完美，允许文档后续迭代

## 常见需澄清的场景

| 缺失信息 | 提问方向 | 示例 |
|---------|---------|------|
| 不清楚角色 | 系统有哪几类用户？ | 普通用户、管理员、商户 |
| 不清楚页面 | {模块}下需要几个页面？ | 列表页、详情页、新增表单 |
| 不清楚交互 | 用户在{页面}能做什么？ | 查看、搜索、新增、编辑、删除 |
| 不清楚规则 | {功能}有什么限制？ | 每人每天限3次、需审批 |
| 不清楚权限 | 不同角色看到的有区别吗？ | 管理员可编辑，普通用户只读 |
| 不清楚状态 | {对象}有几种状态？ | 草稿、待审核、已发布、已下架 |

## 追问技巧

| 用户回答 | 追问方向 |
|---------|---------|
| 笼统描述 | "能举一个具体场景吗？" |
| "和XX一样" | "XX有那么多功能，最常用的是哪几个？" |
| "都要" | "如果必须排优先级，最先做哪个？" |
| "看情况" | "最常见的具体情况是什么？" |
| 回答含糊 | "让我确认一下：{复述理解}，对吗？" |

## 不需要澄清的

以下信息不影响文档生成，不需要主动追问：

- 项目背景和触发因素
- 成功指标和量化目标
- 竞品分析和差异化
- 技术选型和架构方案
- 非功能需求（性能、安全）
- 上线时间和工期
